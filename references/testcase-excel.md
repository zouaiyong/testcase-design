# Excel 格式测试用例输出规则

质量遵 `testcase-design-rules.md`。本文件只约束 **CSV 物理格式**（Excel / WPS 可打开；不生成 `.xlsx`）。

路径与「同一需求只写一份文件」的规则见 `SKILL.md` 第二 / 三节。

---

## 固定 10 列（顺序不可改）

编码 **UTF-8 with BOM**（文件头 `\uFEFF`），分隔符英文逗号。含逗号/引号/换行的字段用双引号包裹，内部 `"` 写成 `""`。
注意：多数编辑器 / Write 工具写出的文件**不带 BOM**，Excel 直接打开中文会乱码。写完后运行 `python scripts/validate_testcase.py --fix-bom <csv>` 补齐，再交付。

**范围声明的归属**：固定 10 列没有位置放范围声明，不要为它在 CSV 里加行或加列。缺口 / 待确认在相关用例的「预期结果」或「备注」列标【待确认】。给人拍板的范围、待确认和高危断言写在同目录的 `{需求名称}-评审指引.md`（见 `review-guide.md`），不在 CSV 加列，也不只写在回复正文里。

| 列序 | 列名 | 约束 |
|------|------|------|
| 1 | 功能模块 | 同类行取值一致，便于筛选 |
| 2 | 功能测试点 | 对应 XMind 的功能点或场景分组（字段 / 规则分支），不要填「功能测试」 |
| 3 | 验证维度 | 只能填 `testcase-design-rules.md` 2.2 的 11 个标准名之一 |
| 4 | 用例标题 | 写法与长度见 `testcase-design-rules.md` 第三节 |
| 5 | 优先级 | 只允许 `高` / `中` / `低`，对应与分配依据见 `testcase-design-rules.md` 第三节 |
| 6 | 前置条件 | 执行前状态与数据，不写操作；无则 `无`。写法见 `testcase-design-rules.md` 第三节 |
| 7 | 测试步骤 | 带序号，每步一个动作、写具体值、不含判定，多步换行（字段整体加引号）。写法见第三节 |
| 8 | 预期结果 | 每行一个判定，多条换行（字段整体加引号）。写法见第三节 |
| 9 | 实际结果 | 生成时填 `—` |
| 10 | 备注 | 无则留空（仍要保留列） |

排列：模块 → 功能点 → 维度（顺序见 `testcase-design-rules.md` 2.2）→ 同维度高优先级在前。字段值不要以 `=` `+` `-` `@` 开头（Excel 当公式）。

下面样例只演示列结构与转义。需求未给提示原文或表结构时，预期只写可见层或【待确认】，**禁止把样例里的句子抄成已确认事实**。

```csv
功能模块,功能测试点,验证维度,用例标题,优先级,前置条件,测试步骤,预期结果,实际结果,备注
注册页-提交区,手机号,功能测试,仅填未注册的11位手机号和正确验证码，点击注册,高,用户未注册,"1. 打开注册页面
2. 输入手机号 13800001111
3. 获取并输入正确验证码
4. 点击注册","1. 注册成功
2. 页面跳转至首页",—,
```
