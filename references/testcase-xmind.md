# XMind 格式测试用例规则

质量、范围声明、覆盖方法一律遵 `testcase-design-rules.md`。本文件只约束 **XMind 兼容 Markdown 的层级**。

交 Markdown，用 XMind 按标题导入，不直接生成 `.xmind`。

路径：`testcases/{需求名称}-测试用例.md`（`-` 连接）。**同一需求只写一份文件**，不论条数；禁止拆成 `-01`/`-02`。用户指定了目录则写到该目录；仅当用户明确要求拆分时才分文件。

---

## 层级

导入 XMind 后，中心是 `#`，往外一圈是模块。Markdown 只有六级标题，所以 **「预期明细」必须用 `-`，不能再开 `#######`**。

| Markdown | 含义 | XMind |
|----------|------|-------|
| `#` | 全文仅一个。一份文件对应一次需求 / 迭代时：`# {需求名}` | 中心 |
| `## 范围声明` | 有内容才放在 `#` 后、第一个业务 `##` 前。人工评审指引是另一份文件，不要写进脑图 | |
| `##` | 模块：页面、Tab、弹框、或一块业务能力（如「揽收超时识别」）。单模块也不可省 | 一级 |
| `###` | 功能点（如「查询」「排除规则」「导出场」） | 二级 |
| `####` | **场景分组**（字段、规则分支、页面区域）；该功能点无需再拆时，本级**直接写用例标题** | 三级 |
| `#####` / `######` | 有分组：标题 `#####`、预期 `######`。无分组：标题在 `####`、预期 `#####`。预期标题只能是 `预期结果` | 用例的子节点 |
| `-` | 预期明细，每条一个子主题 | 预期结果的叶子 |

**有分组**（筛选项、多字段、多规则分支时用这个，也是最常见写法）：

```text
## 模块
### 功能点
#### 字段或规则分支
##### 条件 + 操作 【高/中/低】
###### 预期结果
- 明细
```

**无分组**（该功能点下每条本身就是一个完整场景，不必再插一层空分组）：

```text
## 模块
### 功能点
#### 条件 + 操作 【高/中/低】
##### 预期结果
- 明细
```

禁止 `###` 下面直接 `#####`。`预期结果` 四个字不能写成「期望」或「结果」。标题不要 `**` / `*` / 反引号，行尾不要空格。用例标题行末标 `【高】` / `【中】` / `【低】`（对应见 `testcase-design-rules.md` 第三节），不要写 `（P0）` 或 TC 编号。

识别一条用例的办法：某个标题的**直接子标题**是 `预期结果`，该标题就是用例节点。

模块名带上位置，如 `物流轨迹Tab-筛选区`。复杂跨模块链路可单建 `## 端到端流程`，下分基本流 / 备选流 / 异常流；这是模块名，不是维度名。收条数时不要把端到端主流程砍掉。

`#####` / `####` 用例标题下只保留 `预期结果`，不写前置条件和测试步骤（要前置/步骤走 Excel/CSV）。

## 示例

```markdown
# 用户注册

## 范围声明
**需求来源**：…（有文档链接才写）
**不测**：不涉及登录鉴权。

### 需求缺口 / 需确认项
- 超限提示文案未给出。【待确认】

## 注册页-提交区

### 提交注册

#### 手机号
##### 仅填未注册的11位手机号和正确验证码，点击注册 【高】

###### 预期结果
- 注册成功，页面跳转至首页
- 创建该手机号对应账号

##### 输入已注册手机号和正确验证码后点击注册 【高】

###### 预期结果
- 拦截且不创建新账号
- 提示文案【待确认】

#### 验证码
##### 验证码过期后点击注册 【中】

###### 预期结果
- 提交被拒，须重新获取验证码
```

需求未给库表或提示原文时，不要把示例里没有的字段 / 文案写成已确认事实。
