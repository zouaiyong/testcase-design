# 软件功能测试用例设计规则

本规则是用例质量约束的**单一事实源**（需求来源获取、需求拆解、范围声明、方法、维度、数量、自检与禁止）。交付格式与形态以 `SKILL.md` 判定为准。第五章「完整可执行结构」（前置/步骤/预期）用于 **Excel**，以及用户明确要求完整版时的 **XMind**。形态扫描见下文 3.3。

---

## 一、工作流

需求 → ①按 SKILL **勾选**交付格式与形态（未勾选不得进入设计）→ ②用例设计 → ③按对应格式文件排版。

本文件不复述 SKILL 的勾选与判定表。记住：**未勾选禁止生成**；勾选 XMind 且未要求完整版则为仅标题级；**Excel 固定完整版**；用户 **@ 显式引用**某 reference 时以被引用文件为准。

**分批输出**：超 50 条按功能点分批，每批做一轮自检再继续下一批。

---

## 二、需求拆解（生成前必做）

禁止拿到需求直接写用例。须先完成：识别功能边界（做什么/不做什么）、提取显式业务规则、标记隐含规则（用 **`【隐含规则】`** 前缀）、理清状态流转与数据流向。需求不完整时须**提示用户补全后再开始**。

### 2.1 需求来源获取

同一次任务内信息须完整。不完整则在范围声明列出缺口，补全前不得声称已覆盖。

| 来源 | 须确认/获取 |
|------|-------------|
| 粘贴文本 / 口头 | 有无遗漏附件、流程图、变更记录 |
| 本地 Word / PDF / 图片 | 全文、内嵌图表与附件；图表须可读 |
| 在线文档（Confluence / Notion 等） | 正文、评论/批注、内嵌图表；拉不到评论则列入缺口 |
| **飞书 Wiki / 云文档** | 下面四类缺一不可 |

飞书四类：

| 类别 | 要求 |
|------|------|
| **正文与结构** | 主文、标题层级、表格、列表；宜拉块树，避免表格被压平后丢语义 |
| **图片与附件** | 枚举图片块、文件块，取得可访问副本；禁止只停在占位文件名 |
| **画板** | 导出为图片或记录稳定链接 + 摘要；流程图只在画板里时不得省略对应测试点 |
| **评论** | 全文评论与划词评论（含作者、是否已解决、锚点）；澄清与范围变更并入拆解 |

- 环境中有飞书文档类 skill、MCP 或开放平台接口时优先使用；没有则按用户提供的正文/导出件分析，并写明未拉到的部分。
- 权限、token、鉴权失败不得误报为「文档无评论/无画板」；把失败原因和缺口写入范围声明。本 skill 不绑定特定登录规则文件。

### 2.2 范围声明

`#` 标题后、首个业务 `##` 前输出 `## 范围声明`（全文仅此一处）。固定 4 块加粗小标题 + 可选「交付说明」：

| 小标题 | 写什么 |
|--------|--------|
| **需求来源** | 文档链接、条目/章节、原型（无则写无） |
| **形态扫描** | 只列**适用**形态；需求明确排除的写一两项即可。不要把登录/注册/上传等无关项逐行列 N/A |
| **需求缺口 / 需确认项** | 列表；不确定标【待确认】 |
| **【隐含规则】** | 需求未写但影响用例的约定；无则写无 |

```markdown
## 范围声明
**需求来源**：…
**形态扫描**
| 形态 | 适用 | 说明 |
| 列表 | 是 | 订单列表查询与分页 |
| 导入导出 | N/A | 需求明确不涉及（仅排除项才写 N/A） |

### 需求缺口 / 需确认项
- …。【待确认】

### 【隐含规则】
- …
```

**风险与测试深度**：资金/数据安全 → 判定表全组合、非法/越界各 1 例、关键分支零遗漏；核心链路 → 高密度；多条件组合 → 判定表/正交；新增/重构 → 高于存量；历史高缺陷区 → 额外回归；低频/辅助 → 基本覆盖。

## 三、关键约束

### 3.1 设计方法

按需选用**合适**方法（等价类、边界值、判定表、状态迁移、场景法、错误推测、正交试验），不要求逐条标注；**小需求用等价类 + 边界即可，无需穷举所有方法**。重叠时只写一套用例。

- **等价类**：每输入字段分有效/无效类，每类 1 个代表值；一条用例只验证一个无效类（避免缺陷屏蔽）。同一校验的多种等价写法（空字符串/null/未传）属**同一等价类**，选一个代表值，不逐个建档。
- **边界值**：有明确范围时测边界及相邻值（与边界维度同值不重复建档）：

| 类型 | 测试点 |
|------|--------|
| 数值 [min, max] | min-1, min, min+1, max-1, max, max+1 |
| 字符串长度 [0, N] | 空串, 1 字符, N-1, N, N+1 |
| 日期 | 首日, 末日, 跨月, 跨年, 闰年 2 月 29 日 |
| 集合/列表 | 空集, 1 条, 满页, 超限 |
| 分页 | 第 1 页、最后一页、仅 1 页、每页条数整除/有余数 |
| 金额 | 0, 0.01, 最大限额, 最大限额+0.01 |
| 枚举/下拉 | 首项、末项、枚举外非法值 |
| 布尔 | true, false, null/未传, 非布尔（如 `"true"`） |
| 文件 | 0KB、最小有效、刚好上限、超上限 |

- **判定表**：结果由 ≥2 个条件共同决定时，列条件 → 合并不可能或同结果组合 → 每有效组合至少 1 条。资金/权限等高风险三因素优先判定表，勿只用正交。
- **状态迁移**：全状态图 → 合法路径（含回退/驳回）→ 非法转换拦截 → 并发变更一致性。
- **场景法**：主成功、备选、异常（中断/依赖故障）、回退（返回/刷新/重开后的数据保持）。
- **正交试验**：参数 ≥3 且多取值时压缩两两组合；高风险三因素仍须判定表或显式组合补充。
- **错误推测**：空值族、特殊字符/超长、连点、弱网、时区等；与异常/安全/并发重叠时只写一套。

**反向用例须有独立触发**（禁止「镜像复制」——正向改一词变反向、前置步骤照抄）。前置与触发都须与正向不同：例如正向「合法号注册成功」，反向不是「合法号注册失败」，而是「已注册号重复提交被拦截」。触发可从下表取：

| 触发来源 | 典型场景 |
|---------|---------|
| 非法输入 | 格式错、类型错、超长、空值族、特殊字符、枚举外值 |
| 状态不满足 | 已取消再支付、已删除再编辑 |
| 权限不足 | 角色越权、数据范围外、Token 缺失/过期（归权限维度） |
| 依赖故障 | 下游不可用、超时、第三方错误、库异常回滚 |
| 时序错位 | 验证码/会话过期、步骤颠倒 |
| 并发抢占 | 同数据并发修改、连点重复提交、乐观锁冲突 |
| 边界越界 | 超上限/下限、超额度、超容量（与边界维度协同） |

### 3.2 覆盖维度

11 种标准维度（**此处的排列顺序即维度规范顺序，单一事实源**；Excel/XMind 输出排序、测试要点类别均引用此序）：**功能测试、边界测试、异常测试、权限测试（按需）、安全测试（按需）、数据一致性测试、并发测试（按需）、集成测试（按需）、性能测试（按需）、兼容性测试（按需）、用户体验测试（按需）**。

- **以功能测试为主**。小需求（开关、配置、单一展示/查询等）只需覆盖功能，必要时补少量关键边界/异常即可，**不强制铺满各维度**。
- **权限测试、安全测试默认不生成**，仅在「用户明确要求」或「登录鉴权 / 资金 / 数据安全等高风险场景」时才写。
- **功能测试不得整类省略**；边界/异常按风险与规模补充，小需求无适用场景可不写。
- 每条用例**只归一个维度**，以主判定点决定归属。

**归维（操作规则，不另开章节）**：

- 输入校验不单列维度：必填/唯一/关联/业务规则 → 功能；极值与长度 → 边界；非法格式、类型错 → 异常。
- 业务规则成败 → 功能；格式/类型/单点失败 → 异常；单接口契约与错误 → 异常；跨模块 / MQ / 回调 / 端到端链路 → 集成。
- 身份 / 角色 / 数据范围 / Token 有效性 → **权限**（Token 过期/伪造归权限，不归安全）；防篡改、防注入、防泄露 → **安全**。
- 单点依赖失败 → 异常；链路级与多系统 → 集成。
- 裁剪底线：无登录不写权限；无客户端通常不写兼容性；性能/兼容性按需。
- 无 UI / 纯 API：「页面、加载、跳转」映射为响应体/状态码、可观测耗时或异步状态、资源路径或状态迁移；兼容性常省略；用户体验仅在有 CLI/SDK/错误码等人机约定时按需写。

### 3.3 形态扫描

设计前对照需求判断像哪类能力（登录、注册、列表、表单、删除、导入导出、审批、上传、消息、报表、API、配置等），**只把适用的写入范围声明**。需求明确排除的写一两项即可，**不要**为对照清单把无关形态逐行列 N/A。

- 适用形态须覆盖主成功路径；按风险补充关键备选/异常/回退。**小需求不强制凑齐备选/异常/回退**。
- 命中下列条件时，对应覆盖不要漏（不必另开章节、不必为未命中的条件写 N/A）：
  - **对外 HTTP/API** → 异常测试覆盖错误与超时契约；权限/安全按需；幂等/一致性按需求落在功能或数据一致性
  - **状态/审批/流程** → 状态迁移（合法/非法转换、驳回或回退），禁止只测单步
  - **异步/消息/回调/第三方联动** → 集成测试（链路级）与异常测试（单点失败）按分工落用例
  - **列表/分页/导入/报表** → 与本需求字段、分页、批量、时间范围相关的边界有着落

### 3.4 数量基准

| 需求规模 | 建议条数 |
|---------|---------|
| 简单功能点（开关配置等） | 3~6 |
| 标准功能点（CRUD 页面等） | 6~15 |
| 复杂功能点（审批流/多条件计算） | 15~30 |
| 多功能点汇总 | 各功能点相加 |

- 用户指定条数时以用户为准。**以最少用例覆盖核心功能为目标，宁少勿凑数**。
- 不设边界/异常/安全的强制占比；按需求风险决定是否补充，**不为达标灌水**。
- 同一功能的多个等价/边界输入合并为代表性用例，避免逐值展开。

## 四、用例编写规范

**好用例五项标准**：**原子性**（一条一个核心判定点）、**独立性**（不依赖其他用例执行结果）、**可复现**（按描述操作结果一致）、**可判定**（预期可直接 Pass/Fail）、**可追溯**（对应需求或业务规则）。

- **场景描述**：关键条件 + 关键操作 + 判定方向。好：`管理员搜号后点禁用`。差：`测试搜索功能`。
- **标题长度（单一事实源）**：标题正文不超过 **21 个汉字**。只数汉字；阿拉伯数字、拉丁字母、空格、标点不计入。编号 `TC1-001` 与末尾 `（P0）`/`（P1）`/`（P2）` 也不计；Excel 为「用例标题」列按同一规则数汉字。超长时删菜单路径、字段罗列、具体文案，**保留**条件 + 操作 + 判定方向（成功/拦截/为空/只读等）。XMind / Excel 只引用本条，不另定字数。
- **独立性的落地**：独立性指**不依赖其他用例的执行结果**。用例所需的数据/状态（如「已存在 1 条待审批订单」「该手机号已注册」）一律写入**前置条件**由执行者准备，**禁止**用「先执行 TC00x 造数据」「接上一条」等方式铺垫，避免形成隐性依赖链。删除、驳回、回退等天然依赖既有数据的用例，其数据来源必须落在前置条件里。
- **预期结果**：须可 Pass/Fail，含可见层；**数据层按需且不得臆造**——仅当需求/设计已提供数据契约（表名、字段、状态值）时才写库断言（如 `status=1`），否则只写可见层，必要时把数据层标【待确认】。禁止「系统正常」「符合预期」，禁止为凑「数据层」编造不存在的表结构（与第六章「臆造已确认事实」一致）。需求未定义的提示文案写「（具体文案以实际为准）」或标【待确认】。
- **编号**：`TC{批次}-{三位数}`（如 TC1-001），批次内连续不跳号。单模块可用 `TC001`。
- **优先级**：P0（阻塞发布）、P1（影响完整性）、P2（不影响主流程），标在标题末尾括号内 `（P0）`。

### 跨形态优先级映射

三种交付形态写的是同一套优先级，只是字面不同。**映射的单一事实源在此**；Excel / 测试要点规范只引用，不另定义。

| 形态 | 写法 | 对应 |
|------|------|------|
| XMind 标题级 / 完整版 | `（P0）` / `（P1）` / `（P2）` | P0 阻塞发布；P1 影响完整性；P2 不影响主流程 |
| Excel / CSV | `高` / `中` / `低` | 高=P0，中=P1，低=P2 |
| 测试要点 | `【高】` / `【中】` / `【低】` | 高=P0，中=P1，低=P2 |

## 五、用例设计结构（Markdown 层级）

统一内部格式，最终按用户选择的格式（XMind/Excel）转换输出。

| 层级 | Markdown | 含义 |
|------|----------|------|
| 1 | `# …` | 文档标题 |
| 2 | `## …` | 一级模块 |
| 3 | `### …` | 功能点 |
| 4 | `#### …` | 验证维度（仅使用 3.2 标准维度名） |
| 5 | `##### {编号} {标题}（优先级）` | 单条用例 |
| — | 正文 | 前置条件（推荐；Excel 必填） |
| 6 | `###### 测试步骤：` | 固定标题，下接有序列表 `1. 2. 3.`（推荐；Excel 见列 8） |
| 6 | `###### 预期结果` | 固定标题 |
| — | `- …` | 可判定项（预期结果，无序列表） |

**示例**：

```markdown
##### TC1-001 合法号验证码提交注册（P0）

前置条件：用户已登录管理员账号，该手机号未注册。

###### 测试步骤：
1. 打开注册页面
2. 输入手机号 13800001111
3. 获取并输入正确验证码
4. 点击注册

###### 预期结果
- 注册成功，页面跳转至首页
- 数据库 user 表新增一条记录，status=1
```

**Excel 列映射**：模块→列2，功能点→列3，维度→列4，编号→列1，标题→列5，优先级→列6，前置→列7，步骤→列8，预期→列9。

## 六、自检与禁止

**输出前自检（须全部满足）**：

- [ ] 交付格式已由用户勾选或本轮已明示；未勾选时未生成；XMind 未要求完整版则为仅标题级，Excel 用完整版；超 50 条已分批
- [ ] 范围声明在首个业务 `##` 前，含需求来源、形态扫描（只列适用项，外加需求明确排除的少数项）、缺口/待确认、【隐含规则】
- [ ] 飞书来源已取全正文/图片/画板/评论，或缺口已写入范围声明（鉴权失败未报成「无评论/无画板」）
- [ ] 显式规则与【隐含规则】均有对应用例，或已在范围声明中标注缺口
- [ ] 选用了合适的设计方法（非仅正向场景法）
- [ ] 功能测试不整类缺；每条一个维度；权限/安全仅在按需场景出现
- [ ] 已合并等价/边界输入，无为凑数的冗余用例
- [ ] 含写操作 / 对外 API / 资金场景时，已考虑幂等与重复提交（不适用可不写，但须确认过）
- [ ] （完整形态）预期结果可 Pass/Fail；场景描述具体；无重复用例；结构符合第五章层级
- [ ] 每条标题正文不超过 21 个汉字（阿拉伯数字、字母、标点、空格不计入；不含编号与末尾优先级）
- [ ] 编号连续

**硬性禁止**：

- 未勾选交付格式就生成用例或测试要点
- 臆造已确认事实；空泛预期（「系统正常」「符合预期」）
- 重复用例；仅正向或虚增边界/异常/安全凑数；真实敏感数据作例
- 小需求堆砌权限/安全/兼容等非必要维度，偏离「覆盖核心功能」目标
- 跳过适用形态声明（除非用户已收窄范围并说明）；把无关形态逐行列满 N/A 凑表
- **过度拆分**：同一校验的多种等价输入拆成多条——选一个代表值即可
- **镜像复制**：正向改一词变反向，前置和步骤照抄——反向用例须有独立触发条件
- **标题超 21 个汉字**：把路径、字段清单、文案塞进标题
- **凭空编造提示文案**：需求未定义的文案须标【待确认】
