# 软件功能测试用例设计规则

本规则是用例质量的**单一事实源**。交付格式与形态以 `SKILL.md` 勾选为准；未勾选禁止生成。排版分别遵 xmind / excel 指南。形态扫描见 3.3。

---

## 一、工作流

需求 → ①SKILL 勾选格式 → ②本文件做拆解与设计 → ③按对应格式文件排版。

记住：勾选 XMind 且未要求完整版 → **精简版**（标题 + 预期，无前置/步骤）；**Excel 固定完整版**；用户 **@ 显式引用**某 reference 时以被引用文件为准。条数多时按功能点**分段自检**，但仍写入**同一份文件**；禁止因超过某条数拆成多份。

---

## 二、需求拆解（生成前必做）

先划清做什么/不做什么、显式规则、**`【隐含规则】`**、状态与数据流。不完整则提示补全，禁止直接开写。

### 2.1 需求来源获取

缺口写入交付物（见 2.2），补全前不得声称已覆盖。

| 来源 | 须获取 |
|------|--------|
| 粘贴 / 口头 | 有无遗漏附件、流程图、变更 |
| 本地 Word / PDF / 图片 | 全文与可读图表 |
| 在线文档 | 正文、评论、图表；拉不到评论则列入缺口 |
| **飞书 Wiki / 云文档** | 下面四类缺一不可 |

飞书四类：**正文与结构**（宜拉块树，避免表格被压平）、**图片与附件**（要可访问副本，禁止只停在文件名）、**画板**（导出图或链接+摘要；流程图只在画板里时不得省略）、**评论**（全文+划词，含是否已解决；澄清并入拆解）。

环境有飞书文档 skill/MCP 时优先用；没有则按用户正文/导出件分析并写明未拉到的部分。鉴权失败不得报成「文档无评论/无画板」。

### 2.2 范围声明（有内容才输出，禁止用「无」凑块）

拆解时必须想清：来源、不测什么、缺口、隐含规则。**写进交付物的只是其中有内容的项**；四项都空则整段省略，不要为格式写「无」。

Markdown（XMind）若有内容：放在 `#` 后、首个业务 `##` 前，至多一处 `## 范围声明`。不要形态表（形态只做 3.3 设计检查，不输出）。

| 有则写 | 怎么写 |
|--------|--------|
| **需求来源** | 仅当有文档/章节链接时一行；用户粘贴正文则省略 |
| **不测** | 需求明确排除的范围，一句话（如「不涉及核销、领取」） |
| **需求缺口 / 需确认项** | 不确定标【待确认】；没有缺口则整段省略 |
| **【隐含规则】** | 未写但会影响用例的约定；没有则省略 |

```markdown
## 范围声明
**需求来源**：飞书 Wiki …（章节名）
**不测**：不涉及审批流、支付。

### 需求缺口 / 需确认项
- 超限提示文案未给出。【待确认】

### 【隐含规则】
- 买货季条件不可清空。
```

测试要点的缺口/待确认仍写在文末「风险与回归提示」，不套本段四格。

## 三、关键约束

### 3.1 方法（按需，不必标注方法名）

小需求用等价类 + 边界即可。**同一 `###` 功能点内**方法重叠只写一套；禁止把不同功能点抽成一条公共用例。

- 同一校验的空字符串 / null / 未传属**同一等价类**，留一个代表；一条用例只验证一个无效类。
- **合并只限同一功能点内**。查询/筛选：同一查询区多个条件若判定点相同（填值后列表只出命中行），必须合并，不要每个条件下各写一条。同类控件（多个多选、多个精确输入）只留一个代表 + 必要时一条多条件组合 + 一条重置。有独立规则才拆开（必填/默认、区间边界、批量语法、改变其它模块计数等）。差：`按品类查询`、`按款号查询`、`按月份查询`。好：`多条件查询命中对应行`。
- **禁止跨功能合并**：同一规则出现在多个入口（导入与在线编辑、提交与审核等），分别写在对应 `###` 下，不要抽成跨功能的公共校验点。差：`### XX校验` 下写「导入或保存均…」。好：各入口功能点下各写（规则相同也要各写，提示/拦截方式可以不同）。
- 有明确范围才测边界，不与功能/异常重复建档。
- ≥2 条件共同决定结果用判定表；资金/权限三因素不要只用正交。
- 审批/状态：合法转换、非法转换、驳回或回退都要有，禁止只测单步。
- **禁止镜像复制**：反向须有独立前置与触发。正向「合法号注册成功」，反向不是「合法号注册失败」，而是「已注册号重复提交被拦截」。

### 3.2 覆盖维度

11 个标准维度名（**排列顺序即输出顺序，单一事实源**）：**功能测试、边界测试、异常测试、权限测试（按需）、安全测试（按需）、数据一致性测试、并发测试（按需）、集成测试（按需）、性能测试（按需）、兼容性测试（按需）、用户体验测试（按需）**。

- 以功能为主。小需求不必铺满；**权限/安全默认不写**，除非用户明确要求，或登录鉴权 / 资金 / 数据安全。
- **功能测试不得整类省略**。每条只归一个维度（主判定点）。

**归维**：

- 必填/唯一/业务规则 → 功能；极值与长度 → 边界；非法格式/类型错 → 异常。
- 单接口错误与超时 → 异常；跨模块 / MQ / 回调 / 端到端 → 集成。
- 身份/角色/数据范围/Token → **权限**（过期/伪造归权限，不归安全）；注入/篡改/泄露 → **安全**。
- 无登录不写权限；无客户端通常不写兼容。无 UI 时把「页面/跳转」映射为响应体、状态码或资源状态。

### 3.3 形态扫描（设计检查，不写入交付物）

对照需求判断像哪类能力（列表、表单、导入导出、审批、API 等）。**只用来决定覆盖，不要输出形态表，不要为未命中项写 N/A。**

- 适用形态覆盖主成功路径；小需求不强制凑齐备选/异常/回退。
- 命中才补：
  - **对外 HTTP/API** → 错误与超时契约；幂等按需求落功能或一致性
  - **状态/审批/流程** → 合法/非法转换、驳回或回退
  - **异步/消息/回调/第三方** → 集成（链路）与异常（单点失败）
  - **列表/分页/导入/报表** → 筛选机制（命中/组合/重置，**不按字段逐条铺**）、分页、批量；某字段有独立规则（区间、批量语法等）才单列

### 3.4 覆盖与条数

显式规则、【隐含规则】和 3.3 命中的形态该测的都要覆盖到。**宁少勿凑**：仅在同一功能点内做等价输入合并、查询/筛选同类条件合并；不为凑条数灌水边界/异常/安全、也不按表单或查询字段逐条铺。**不得**为少条数把导入与编辑等不同功能并成一条。资金/核心链路加密度；低频辅助点到为止。用户指定条数时以用户为准。

## 四、用例编写规范

- **标题**：条件 + 操作 + 判定方向。好：`管理员搜号后点禁用`。差：`测试搜索功能`。
- **标题长度（单一事实源）**：正文不超过 **21 个汉字**（只数汉字；数字、字母、标点、空格不计）。不含 `TC1-001` 与末尾 `（P0）`/`（P1）`/`（P2）`。Excel 为「用例标题」列按同一规则数汉字。超长先砍路径、字段清单、文案。XMind / Excel 只引用本条。
- **独立性**：禁止「先执行 TC00x」。完整版把所需数据/状态写入**前置条件**；精简版无前置，条件写进标题，须能独立理解。
- **预期**：可 Pass/Fail。需求没给表结构就不要写 `status=1` 这类库断言；没给文案就标【待确认】或「以实际为准」。禁止「系统正常」。
- **编号**：`TC{批次}-{三位数}`，连续不跳号；单模块可用 `TC001`。
- **优先级**：P0 阻塞发布、P1 影响完整性、P2 不影响主流程。

### 跨形态优先级映射

| 形态 | 写法 | 对应 |
|------|------|------|
| XMind | `（P0）` / `（P1）` / `（P2）` | 同上 |
| Excel / CSV | `高` / `中` / `低` | 高=P0，中=P1，低=P2 |
| 测试要点 | `【高】` / `【中】` / `【低】` | 高=P0，中=P1，低=P2 |

## 五、内部 Markdown 层级

`#` 文档 → `##` 模块 → `###` 功能点 → `####` 3.2 维度名 → `##### TC… 标题（P0）`。

精简版：`#####` 下只写 `###### 预期结果` + `-`，禁止前置和 `###### 测试步骤`。完整版再写前置、`###### 测试步骤：` + `1. 2. 3.`、`###### 预期结果` + `-`。样例分别见 xmind / excel 指南，不要把指南里的库表字段抄成已确认事实。

Excel 列：编号→1，模块→2，功能点→3，维度→4，标题→5，优先级→6，前置→7，步骤→8，预期→9。

## 六、禁止

- 未勾选交付格式就生成
- 臆造已确认事实（库表、提示原文）；空泛预期
- 仅正向或灌水边界/异常/安全；小需求堆权限/安全/兼容
- 输出形态扫描表或用「无」把范围声明凑成四块
- 因条数（如超 50 条）把同一需求拆成多份用例文件
- 精简版写出前置条件或测试步骤，或漏写预期结果
- 空/null/未传拆成多条；查询/筛选一条件一条；跨功能合并（不同入口的同一规则抽成公共「XX校验」）；镜像复制；标题超过 21 个汉字
- 真实敏感数据作例

输出前核对：有缺口/排除/隐含规则已写入交付物（无则不要空段）；功能测试不缺；权限/安全仅按需；查询/筛选同类条件已在同一功能点内合并且未跨功能合并；写操作/对外 API 已考虑幂等（不适用可跳过但须想过）；编号连续。
