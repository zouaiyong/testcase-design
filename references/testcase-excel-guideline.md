# Excel 格式测试用例输出规则

本规则**仅约束输出格式**。用例的设计方法、覆盖维度、质量标准、数量基准等统一遵循 `functional-testcase-design.md`。

由于无法直接生成 `.xlsx` 文件，实际输出为 **CSV 格式**（UTF-8 编码），可被 Excel / WPS / Google Sheets 直接打开和编辑。

---

## 1) 文件命名与路径

- 输出路径：`testcases/{需求名称}-测试用例-{序号}.csv`
- 命名统一用 `-` 连接。
- 同一批需求汇总到**一个文件**，不拆分。

---

## 2) CSV 基础格式

- 编码：**UTF-8 with BOM**（确保 Excel 打开中文不乱码）。
- 分隔符：英文逗号 `,`。
- 字段包含逗号、双引号或换行时，必须用**双引号**包裹，双引号本身用 `""` 转义。
- 第一行为**表头行**。

---

## 3) 列结构（固定 11 列）

CSV 必须包含以下 11 列，按此顺序排列：

| 列序 | 列名 | 说明 |
|------|------|------|
| 1 | 用例编号 | `TC001` 或 `TC1-001` 格式递增 |
| 2 | 功能模块 | 所属模块名称 |
| 3 | 功能测试点 | 所属功能点名称 |
| 4 | 验证维度 | 功能测试 / 边界测试 / 异常测试 / 权限测试 / 安全测试 等 |
| 5 | 用例标题 | 简洁描述场景与关键条件 |
| 6 | 优先级 | 仅允许：高 / 中 / 低 |
| 7 | 前置条件 | 执行该用例前需要满足的条件，无则填"无" |
| 8 | 测试步骤 | 带序号的操作步骤，多步骤用换行分隔 |
| 9 | 预期结果 | 具体、可验证、可判定的结果描述 |
| 10 | 实际结果 | 默认填"—"（执行阶段手工填写） |
| 11 | 备注 | 补充说明，如关联需求编号、特殊环境要求，无则留空 |

---

## 4) 各字段填写规范

### 用例编号

- 单模块：`TC001`、`TC002` ... 三位数递增。
- 多模块：`TC{模块序号}-{三位数}`，如 `TC1-001`、`TC2-001`。
- 编号必须连续，不跳号。

### 功能模块 / 功能测试点

- 同模块/同功能点的用例，这两列值保持一致（方便 Excel 筛选和分组）。
- 命名与需求文档中的功能划分对齐。

### 验证维度

- 只能填 `functional-testcase-design.md` 3.2 定义的 11 个标准维度名之一（功能测试 / 边界测试 / 异常测试 / 权限测试 / 安全测试 等），不使用自由文本，保证 Excel 筛选时分类干净。
- 各维度是否默认启用（如权限/安全默认不生成）以 `functional-testcase-design.md` 3.2 为准（单一事实源），本规范不另行规定；小需求以 `功能测试` 为主。

### 用例标题

- 用短句描述场景，体现关键条件和关键操作。
- **不超过 21 个汉字**（计数规则见 `functional-testcase-design.md` 第四章，本规范引用，不另定字数）。
- 不写冗长步骤、菜单路径、字段清单。

### 优先级

- 只允许填 `高`、`中`、`低` 三个值。
- 映射 `高=P0`、`中=P1`、`低=P2`（统一事实源见 `functional-testcase-design.md` 第四章「跨形态优先级映射」，本规范引用，不另行定义）。

### 前置条件

- 写明执行该条用例前系统需要处于什么状态、需要什么数据。
- 如"用户已登录管理员账号"、"系统中已存在至少 1 条待审批订单"。
- 无特殊前置条件则填"无"。

### 测试步骤

- 用带序号的步骤描述，每步一个操作。
- 步骤之间用换行分隔（CSV 中换行包裹在双引号内）。
- 格式示例：
  ```
  1. 打开用户管理页面
  2. 点击"新增用户"按钮
  3. 输入手机号 13800001111
  4. 点击"提交"
  ```
- 步骤必须可复现，指明具体页面、按钮、输入值。

### 预期结果

- 与测试步骤对应，说明每步或最终的可验证结果。
- 多条结果用换行分隔，带序号。
- 格式示例：
  ```
  1. 新增用户弹窗弹出
  2. 提交后提示"新增成功"
  3. 用户列表出现手机号 138xxxx1111 的记录
  ```

### 实际结果

- 生成时默认填 `—`。
- 执行测试时由测试人员手工填写实际表现。

### 备注

- 可填写：关联需求编号、特殊测试环境要求、已知限制、依赖说明。
- 无则留空。

---

## 5) 用例排列顺序

- 按**功能模块 → 功能测试点 → 验证维度**排列。
- 同一功能测试点内，维度顺序遵循 `functional-testcase-design.md` 3.2 的维度规范顺序（单一事实源），本规范不复述名单。
- 同维度内高优先级排前面。

## 7) Excel 特有注意事项

- **CSV 首行加 BOM**：文件开头写入 `\uFEFF`（UTF-8 BOM），否则 Excel 打开中文可能乱码。
- **双引号转义**：字段内的双引号写成 `""`（两个双引号），如预期结果含提示语 `提示"成功"` → CSV 中写 `"提示""成功"""` 。
- **换行处理**：测试步骤和预期结果含多行时，整个字段用双引号包裹，内部用 `\n` 实际换行。
- **避免以 `=` `+` `-` `@` 开头的字段值**：Excel 会将其解析为公式，产生安全风险或报错。如不可避免，在值前加单引号 `'` 或空格。
- **列数固定**：每行必须严格 11 个字段（含空字段也要保留逗号），否则 Excel 列会错位。

## 8) 输出前格式自检

- [ ] 第一行为完整的 11 列表头。
- [ ] 每行字段数 = 11，无列错位。
- [ ] 含逗号/双引号/换行的字段已用双引号包裹且正确转义。
- [ ] 用例编号连续无跳号。
- [ ] 功能模块、功能测试点、验证维度的值在同类用例中保持一致（可筛选）。
- [ ] 优先级只有"高/中/低"三种值。
- [ ] 用例标题不超过 21 个汉字（数字、字母、标点、空格不计入）。
- [ ] 测试步骤有具体操作和数据，不模糊。
- [ ] 预期结果具体可判定。
- [ ] 文件为 UTF-8 with BOM 编码。
- [ ] 用 Excel 或 WPS 试打开确认无乱码无错位。
- [ ] 若由脚本生成：输出文件存在且非空；抽查表头 11 列与编号连续。无法运行脚本时已在回复中说明。
