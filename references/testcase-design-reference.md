# 测试用例设计参考手册

本文件是 `functional-testcase-design.md` 的详细定义参考。核心工作流、约束、自检与禁止仍以核心规则为准。

---

## 一、需求来源的完整获取

无论需求来自何种渠道，须确保同一次分析任务内获取的信息完整。

### 1.1 通用要求

| 来源类型 | 须确认/获取 |
|---------|------------|
| 用户粘贴文本 / 口头描述 | 确认是否完整（有无遗漏附件、流程图、变更记录）；不完整时须提示补全 |
| 本地文件（Word / PDF / 图片） | 获取全文、内嵌图表与附件；图表须可读 |
| 在线文档（Confluence / Notion 等） | 获取正文、评论/批注、内嵌图表；不支持自动拉取评论时须在范围声明中列出缺口 |
| **飞书 Wiki / 云文档** | 见 1.2 |

### 1.2 飞书专项

通过飞书链接、Wiki 节点或云文档拉取需求时，须完成四类信息获取，缺一不可：

| 类别 | 要求 |
|------|------|
| **正文与结构** | 获取主文、标题层级、表格、列表；宜拉取文档块/块树，避免表格被压平后语义丢失 |
| **图片与附件** | 枚举图片块、文件块，取得可访问副本；禁止仅停留在占位文件名 |
| **画板** | 导出为图片或记录稳定链接 + 摘要；流程图仅存在于画板时不得省略对应测试点 |
| **评论** | 获取全文评论与划词评论（含作者、是否已解决、锚点）；评论中的澄清、范围变更须并入需求拆解 |

- 环境中有飞书文档类 skill、MCP 或开放平台接口时优先使用；没有则按用户提供的正文/导出件分析，并在范围声明中写明未拉到的部分。
- 若不支持画板或评论自动拉取：须在范围声明中列出缺口，补全前不得声称需求已完整覆盖。
- 权限、token、鉴权失败不得误报为「文档无评论/无画板」；把失败原因和缺口写入范围声明。按使用者环境已有的登录/授权方式处理，本 skill 不绑定特定规则文件。

## 二、设计方法论（七种）

核心规则要求**按需选用合适方法**（不强制数量；小需求用等价类 + 边界即可，无需穷举），以下为各方法的详细定义与使用要点。

### 2.1 等价类划分

- 每输入字段分有效/无效等价类，每类至少 1 个代表值。
- 一条用例只验证一个无效等价类（避免缺陷屏蔽）。
- **禁止过度拆分**：同一校验规则的多种等价写法（空字符串、null、未传）属同一等价类，选一个代表值。

### 2.2 边界值分析

针对有明确范围的输入，测边界及相邻值：

| 类型 | 测试点 |
|------|--------|
| 数值范围 [min, max] | min-1, min, min+1, max-1, max, max+1 |
| 字符串长度 [0, N] | 空串, 1 字符, N-1, N, N+1 |
| 日期 | 首日, 末日, 跨月, 跨年, 闰年 2 月 29 日 |
| 集合/列表 | 空集, 1 条, 满页, 超限 |
| 分页 | 第 1 页、最后一页、仅 1 页、每页条数整除/有余数 |
| 金额 | 0, 0.01, 最大限额, 最大限额+0.01 |
| 枚举/下拉 | 首项、末项、枚举外非法值 |
| 布尔值 | true, false, null/未传, 非布尔（如字符串 "true"） |
| 文件 | 0KB、最小有效、刚好上限、超上限 |

### 2.3 判定表法

结果由 ≥2 个条件共同决定时：列条件与取值 → 笛卡尔积 → 合并不可能或同结果组合 → 每有效组合至少 1 条。

### 2.4 状态迁移法

订单/审批/工单等：全状态图 → 合法路径（含回退/驳回）→ 非法转换拦截 → 并发变更一致性。

### 2.5 场景法（用户旅程）

**主成功路径**、**备选路径**、**异常路径**（中断/依赖故障）、**回退路径**（返回/刷新/重开后的数据保持）。

### 2.6 错误推测法

经验性查漏（空值族、特殊字符/超长、连点、弱网、时区等）。与异常/安全/并发维度重叠时只写一套用例，标签可叠加。与权限交叉时以权限维度为准。

**反向用例的独立触发来源**（核心规则禁止「镜像复制」——正向改一词变反向、前置步骤照抄；反向用例须有自己的触发条件，可从下表取得，而非把正向取反）：

| 触发来源 | 典型场景 |
|---------|---------|
| 非法输入 | 格式错、类型错、超长、空值族、特殊字符、枚举外值 |
| 状态不满足 | 在错误状态下操作（已取消的订单再支付、已删除的数据再编辑） |
| 权限不足 | 角色越权、数据范围外、Token 缺失/过期（归权限维度） |
| 依赖故障 | 下游不可用、超时、第三方返回错误、库异常回滚 |
| 时序错位 | 验证码/会话过期、操作过期、先后步骤颠倒 |
| 并发抢占 | 同数据并发修改、连点重复提交、乐观锁冲突 |
| 边界越界 | 超上限/下限、超额度、超容量（与边界维度协同） |

- 反向用例的**前置条件与触发操作须与正向不同**：例如正向「输入合法手机号注册成功」，反向不是「输入合法手机号注册失败」，而是「该手机号已注册时重复提交被拦截」——前置(已注册)和触发(重复提交)都是独立的。

### 2.7 正交试验法

参数 ≥3 且多取值时用正交表压缩，保证两两组合被覆盖。资金/权限等高风险三因素仍须判定表或显式组合补充。

## 三、覆盖维度详解（3.1～3.11）

维度名称以本章定义为准。核心规则约束：功能测试不得整类省略，边界/异常按风险与规模补充；每条用例只归一个维度。

**裁剪底线**：无登录不写权限；无客户端通常不写兼容性。性能/兼容性按需。

**无 UI / 纯 API**：「页面、加载、跳转」映射为响应体/状态码、可观测耗时或异步状态、资源路径或状态迁移；兼容性常省略；用户体验仅在有 CLI/SDK/错误码等人机约定时按需写。

**输入校验不单列维度**：必填/唯一/关联/业务规则 → 功能测试；极值与长度 → 边界测试；非法格式、类型错 → 异常测试。

**维度快速判定**：业务规则成败 → 功能；格式/类型/单点失败 → 异常；单接口契约与错误 → 异常；跨模块/MQ/回调/端到端链路 → 集成。权限（身份/角色/Token）与安全（注入/篡改/泄露）划分见 3.5 段首。

### 3.1 功能测试

行为与结果正确：CRUD 与落库、计算与规则、页面或接口与数据源一致、明确反馈（文案友好度归用户体验）；必填为空提示、唯一性、关联校验（如日期顺序、子项金额之和）。

### 3.2 边界测试

数值/长度/数量按 2.2 表取值（min-1, min, min+1, max-1, max, max+1 等）；另含空数据列表展示、批量上限、分页边界。与 2.2 同值不重复建档。

### 3.3 异常测试

格式/类型校验失败；后端 400/500/超时等时调用方表现；依赖不可用降级；库异常与事务回滚；上传失败/断点续传。预期结果须写具体错误表现（提示文案、状态码、页面状态），禁止「系统正常处理」。

### 3.4 权限测试（仅按需）

角色菜单/按钮/数据范围；越权访问 URL 或接口；越权操作；脱敏；Token 缺失/过期/伪造（**鉴权失败归本条，不归安全**）。

### 3.5 安全测试（仅按需）

**与权限的划分**：主判定点为「身份/角色/数据范围/Token 有效性」→ 归权限；主判定点为「防篡改、防注入、防泄露」→ 归本条。注入、XSS、CSRF、泄露、恶意内容、篡改以突破业务约束均归本条。

### 3.6 数据一致性测试

库与展示层一致；缓存与库；级联更新/删除；软删除在查询/统计/关联中正确排除；事务完整性。

### 3.7 并发测试（仅按需）

多终端、多用户同数据、连点防重、批量与单条冲突、乐观锁/重试等。

### 3.8 集成测试

模块间传递；第三方接口成功/失败与联动；消息队列/回调/推送；缓存与库同步策略；上下游级联。与异常的划分：单点依赖失败归异常，链路级与多系统归集成。

### 3.9 性能测试（按需）

大数据量查询；批量操作耗时与资源；高并发吞吐与错误率；前端长列表/大表单渲染。

### 3.10 兼容性测试（按需）

主流浏览器；分辨率；iOS/Android；网络环境（WiFi/4G/弱网）。

### 3.11 用户体验测试（仅按需）

在功能测试已有反馈基础上：是否好懂、好用（引导、防误、冗余跳转）；无 UI 时见纯 API 说明。

## 四、风险与测试深度参考

| 风险因素 | 测试深度 |
|---------|---------|
| 资金/数据安全 | 判定表全组合覆盖；每条非法/越界输入各 1 例；边界齐全；关键分支零遗漏 |
| 核心业务链路（下单、支付、登录等） | 高密度 |
| 多条件组合/复杂计算 | 判定表/正交系统覆盖 |
| 新增/重构 | 高于存量 |
| 历史高缺陷区 | 额外回归 |
| 低频/辅助 | 基本覆盖即可 |
