# XMind 格式测试用例规则

质量、范围声明、标题字数一律遵 `functional-testcase-design.md`。本文件只约束 **XMind 兼容 Markdown 的层级**。

| 形态 | 叶子 |
|------|------|
| **仅标题级**（勾选 XMind 且未要求完整版） | 到 `#####` 为止，**禁止**前置 / `###### 测试步骤` / `###### 预期结果` |
| **完整版**（用户明确要可执行 / 含前置·步骤·预期） | 须有 `###### 预期结果` + `-`；步骤用 `###### 测试步骤：` + `1. 2. 3.` |

输出 `.md`，用 XMind 按标题导入，不直接生成 `.xmind`。不出 Excel。与测试要点的差别：有 **TC、`####` 维度、（P0）**；要点无 TC、用 `-`、用【高/中/低】。

路径：`testcases/{需求名称}-测试用例-{序号}.md`（`-` 连接；默认同批一个文件；超 50 条分批）。指定了目录则写到该目录。

---

## 层级（不得跳级）

| Markdown | 含义 | XMind |
|----------|------|-------|
| `#` | 全文仅一个，`# {需求名}测试用例` | 中心 |
| `## 范围声明` | `#` 后、首个业务 `##` 前，仅一处 | |
| `##` | 功能模块（单模块也不可省） | 一级 |
| `###` | 功能点 | 二级 |
| `####` | 仅 3.2 标准维度名；**功能测试不得缺** | 三级 |
| `##### TC1-001 标题（P0）` | 用例叶子。标题 ≤21 个汉字，须含条件+操作+**判定方向** | 四级 |

好：`已注册号重复提交被拦截`。差：`测试重复注册`、把菜单路径写进标题。

完整形态在 `#####` 下可写 `前置条件：…`（纯文本）；`######` 只用于 `测试步骤：` / `预期结果`；不可再深。标题里不要 `**`、`*`、反引号，行尾不要空格。

---

## 示例

### 仅标题级（优先按此）

```markdown
# 用户管理模块测试用例

## 范围声明
**需求来源**：…
**形态扫描**
| 形态 | 适用 | 说明 |
| 表单 | 是 | 注册表单 |

### 需求缺口 / 需确认项
- 无

### 【隐含规则】
- 无

## 用户管理

### 用户注册

#### 功能测试
##### TC1-001 合法号验证码注册成功（P0）
##### TC1-002 已注册号重复提交被拦截（P0）

#### 边界测试
##### TC1-003 手机号非11位被拦截（P1）

#### 异常测试
##### TC1-004 验证码过期提交被拒（P1）
```

### 完整形态（仅用户明确要求）

```markdown
##### TC1-001 合法号验证码提交注册（P0）

前置条件：该手机号未注册。

###### 测试步骤：
1. 打开注册页面
2. 输入手机号 13800001111
3. 获取并输入正确验证码
4. 点击注册

###### 预期结果
- 注册成功，页面跳转至首页
```

需求未给库表或提示原文时，不要把示例里没有的字段/文案写成已确认事实。

用户要 `.xmind` 且仓库已有转换脚本才运行；没有脚本则交 Markdown 并说明。
