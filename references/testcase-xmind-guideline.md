# XMind 格式测试用例规则（默认精简）

本规则覆盖 **XMind 兼容 Markdown 的输出格式**，以及 **XMind 交付时的默认用例形态（仅标题级）**。

| 约定 | 说明 |
|------|------|
| 设计方法 / 覆盖维度 / 数量基准 / 范围声明 / 需求拆解 | 统一遵循 `functional-testcase-design.md` |
| **默认形态** | 用例到 `#####` 为止（编号 + 标题 + 优先级），**不写**前置条件、测试步骤、预期结果 |
| 完整可执行形态 | 仅当用户明确要求「完整版 / 可执行用例 / 含前置条件或测试步骤或预期结果」时启用 |

本规则输出 Markdown（`.md`），通过 XMind 导入为思维导图，不直接生成 `.xmind`。本形态**不出 Excel/CSV**（Excel 走核心规则 + `testcase-excel-guideline.md`）。

**与测试要点的区别**：本规则保留 **TC 编号、`####` 维度分层、P0/P1/P2**；测试要点（`testpoint-analysis-guideline.md`）无 TC、用 `-` 罗列、用【高/中/低】，粒度更粗。

---

## 1) 文件命名与路径

- 输出路径：`testcases/{需求名称}-测试用例-{序号}.md`
- 命名统一用 `-` 连接，不用空格或下划线。
- 同一批需求默认汇总到**一个文件**，用户要求拆分时除外。
- 超 50 条按功能点分批，每批自检后再继续。

---

## 2) Markdown 层级结构（必须严格遵守）

XMind 通过标题层级解析节点，以下层级**不得跳级、混用、省略**。

### 2.1 默认：精简形态（到 `#####` 为止）

| 层级 | 对应内容 | XMind 节点层 |
|------|---------|-------------|
| `#` | 文档主标题（如：XX模块测试用例） | 中心主题 |
| `##` | 功能模块 | 一级分支 |
| `###` | 功能测试点 | 二级分支 |
| `####` | 验证维度（功能测试 / 边界测试 / 异常测试 等） | 三级分支 |
| `#####` | 用例场景（格式：`{编号} {标题}（优先级）`） | 四级分支（**叶子**） |

**严禁**在默认精简形态下出现：`前置条件：…` 正文、`###### 测试步骤：`、`###### 预期结果`。`#####` 即叶子，其下不再有任何内容。

### 2.2 完整形态（仅用户明确要求时）

在 2.1 各层之上继续展开：

| 层级 | 对应内容 | XMind 节点层 |
|------|---------|-------------|
| `#####` 正文 | 前置条件：`前置条件：…`（可选） | 附于用例节点 |
| `######` | 固定写 `测试步骤：` 或 `预期结果` | 五级分支（标题） |
| `1. 2. …` | 测试步骤正文（有序列表） | 五级下子节点 |
| `-` | 预期结果条目（无序列表） | 五级下子节点（每条一项） |

---

## 3) 层级规则详解

### `#` 文档主标题

- 全文档只有一个 `#`。
- 格式：`# {模块名/需求名}测试用例`。

### `##` 功能模块

- 多模块时每个模块一个 `##`；单模块也不可省略 `##`。
- `#` 后、首个业务 `##` 前须有 `## 范围声明`（全文仅一处；内容遵核心规则。形态扫描只列适用项，明确排除的写一两项即可）。

### `###` 功能测试点

- 每个功能点独立一个 `###`；命名体现功能动作（如「用户注册」「订单取消」）。

### `####` 验证维度

- 仅使用 `functional-testcase-design.md` 3.2 的 11 个标准维度名。
- 权限/安全等是否默认启用以核心 3.2 为准；小需求可只写 `功能测试`，但**`功能测试` 不得缺失**。

### `#####` 用例场景（精简默认的核心差异）

- 格式：`##### TC{模块序号}-{三位数} {场景描述}（优先级）`；单模块可用 `TC001`。
- 末尾优先级：`（P0）`/`（P1）`/`（P2）`。
- 标题正文（编号与末尾优先级之间）**不超过 21 个汉字**，计数与压缩规则见 `functional-testcase-design.md` 第四章，本规范不另定字数。

**精简默认 —— 标题必须自带可判定意图**（没有预期结果兜底）：

- 标题 = **关键条件/角色 + 关键操作/输入 + 预期判定方向**（成功 / 拦截 / 提示 / 进入某状态 / 落库 等），且压进 21 个汉字。
- 好：`已注册号重复提交被拦截`、`手机号非11位被拦截`。
- 差：`测试重复注册`、`验证手机号校验`（看不出测什么、期望什么）；也差：把菜单路径或字段清单写进标题导致超过 21 个汉字。
- 点明期望**方向**即可，**不写**具体提示文案、步骤、落库字段、完整入口路径。

**标题级好用例标准**：原子性、独立性（标题可独立理解）、可评审（仅凭标题判断覆盖）、隐含可判定、可追溯（对应需求或【隐含规则】）。

**完整形态**（仅用户明确要求时）：标题写关键条件 + 关键操作即可；判定细节落在预期结果。可写 `前置条件：…`；`###### 测试步骤：` + `1. 2. 3.`（可省略）；**必须**有 `###### 预期结果` + `-` 列表。

## 4) 示例

### 4.1 默认精简示例（优先按此输出）

```markdown
# 用户管理模块测试用例

## 范围声明
**需求来源**：…
**形态扫描**
| 形态 | 适用 | 说明 |
| 表单 | 是 | 注册表单 |

### 需求缺口 / 需确认项
- 无

### 【隐含规则】
- 无

## 用户管理

### 用户注册

#### 功能测试
##### TC1-001 合法号验证码注册成功（P0）
##### TC1-002 已注册号重复提交被拦截（P0）

#### 边界测试
##### TC1-003 手机号非11位被拦截（P1）

#### 异常测试
##### TC1-004 验证码过期提交被拒（P1）
```

### 4.2 完整形态示例（仅用户明确要求时）

```markdown
# 用户管理模块测试用例

## 范围声明
**需求来源**：…
**形态扫描**
| 形态 | 适用 | 说明 |
| 表单 | 是 | 注册表单 |

### 需求缺口 / 需确认项
- 无

### 【隐含规则】
- 无

## 用户管理

### 用户注册

#### 功能测试

##### TC1-001 合法号验证码提交注册（P0）

前置条件：该手机号未注册。

###### 测试步骤：
1. 打开注册页面
2. 输入手机号 13800001111
3. 获取并输入正确验证码
4. 点击注册

###### 预期结果
- 注册成功，页面跳转至首页
- 数据库 user 表新增一条记录，status=1

##### TC1-002 已注册号再次提交注册（P0）

###### 预期结果
- 提示"该手机号已注册"，不创建新账号
```

## 5) XMind 特有注意事项

- **不要在标题中使用 Markdown 格式符号**（如加粗 `**`、斜体 `*`、代码块）。
- **不要在标题行尾留多余空格**。
- **有序列表仅用于完整形态的 `###### 测试步骤：` 下方**。
- **无序列表仅用于完整形态的 `###### 预期结果` 下方**。
- **精简形态下不要在 `#####` 下使用任何列表或正文**。
- **完整形态下**：前置条件用纯文本 `前置条件：…`，不用列表。
- **层级**：精简最深 `#####`；完整最深 `######`，不可再深。

---

## 6) 输出前自检

**格式**：

- [ ] 全文一个 `#`；范围声明在首个业务 `##` 前
- [ ] 层级严格递进、无跳级；编号连续；UTF-8；标题无 Markdown 符号

**默认精简**：

- [ ] 每条到 `#####` 即止——无前置、无 `######`、无步骤/预期
- [ ] 每条标题自带验证意图（测什么 + 期望方向）；标题正文不超过 21 个汉字
- [ ] 功能测试不整类缺；每条一个维度；权限/安全仅按需
- [ ] 已合并等价/边界输入，无空泛标题、无重复、无镜像复制

**完整形态**（仅用户明确要求时）：

- [ ] 每条有 `###### 预期结果` + `-` 列表；有步骤时为 `###### 测试步骤：` + `1. 2. 3.`

**生成 `.xmind` 文件**（仅用户明确要求时）：

- [ ] 仓库若已有 Markdown→XMind 转换脚本，已运行且无 traceback、输出非空；没有脚本则交付 Markdown 并说明未生成 `.xmind`
- [ ] 已抽查根节点标题与层级与源 Markdown 一致；无法运行脚本时已在回复中说明
