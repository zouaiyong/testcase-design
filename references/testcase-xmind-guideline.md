# XMind 格式测试用例规则

质量、范围声明（有内容才写）、标题字数一律遵 `functional-testcase-design.md`。本文件只约束 **XMind 兼容 Markdown 的层级**。

| 形态 | 叶子 |
|------|------|
| **精简版**（勾选 XMind 且未要求完整版） | 与完整版相同，但**去掉前置条件、去掉测试步骤**；须有 `###### 预期结果` + `-` |
| **完整版**（用户明确要可执行 / 含前置·步骤·预期） | `前置条件：…` + `###### 测试步骤：` + `1. 2. 3.` + `###### 预期结果` + `-` |

输出 `.md`，用 XMind 按标题导入，不直接生成 `.xmind`。不出 Excel。与测试要点的差别：有 **TC、`####` 维度、（P0）**；要点无 TC、用 `-`、用【高/中/低】。

路径：`testcases/{需求名称}-测试用例.md`（`-` 连接）。**同一需求只写一份文件**，不论条数；禁止拆成 `-01`/`-02`。用户指定了目录则写到该目录；仅当用户明确要求拆分时才分文件。

---

## 层级（不得跳级）

| Markdown | 含义 | XMind |
|----------|------|-------|
| `#` | 全文仅一个，`# {需求名}测试用例` | 中心 |
| `## 范围声明` | 仅当有来源/不测/缺口/隐含规则时出现；内容遵 functional 2.2 | |
| `##` | 功能模块（单模块也不可省） | 一级 |
| `###` | 功能点 | 二级 |
| `####` | 仅 3.2 标准维度名；**功能测试不得缺** | 三级 |
| `##### TC1-001 标题（P0）` | 用例节点。标题 ≤21 个汉字，须含条件+操作+**判定方向** | 四级 |
| `###### 预期结果` | 精简版必有；其下用 `-` 写可判定预期 | 五级 |
| `###### 测试步骤：` | **仅完整版**；精简版禁止 | 五级 |

好：`已注册号重复提交被拦截`。差：`测试重复注册`、把菜单路径写进标题。

`#####` 下：精简版只保留 `###### 预期结果`；完整版可写 `前置条件：…`（纯文本）和 `###### 测试步骤：`。`######` 只用于 `测试步骤：` / `预期结果`，不可再深。精简版禁止出现前置和步骤。标题里不要 `**`、`*`、反引号，行尾不要空格。

---

## 示例

### 精简版（优先按此：完整版去掉前置和步骤）

```markdown
# 用户管理模块测试用例

## 范围声明
**需求来源**：…（有文档链接才写）
**不测**：不涉及登录鉴权。

### 需求缺口 / 需确认项
- 超限提示文案未给出。【待确认】

## 用户管理

### 用户注册

#### 功能测试
##### TC1-001 合法号验证码注册成功（P0）

###### 预期结果
- 注册成功，页面跳转至首页

##### TC1-002 已注册号重复提交被拦截（P0）

###### 预期结果
- 拦截且不创建新账号
- 提示文案【待确认】

#### 边界测试
##### TC1-003 手机号非11位被拦截（P1）

###### 预期结果
- 格式校验拦截，不发起注册

#### 异常测试
##### TC1-004 验证码过期提交被拒（P1）

###### 预期结果
- 提交被拒，须重新获取验证码
```

### 完整形态（仅用户明确要求：在精简版上补前置和步骤）

```markdown
##### TC1-001 合法号验证码提交注册（P0）

前置条件：该手机号未注册。

###### 测试步骤：
1. 打开注册页面
2. 输入手机号 13800001111
3. 获取并输入正确验证码
4. 点击注册

###### 预期结果
- 注册成功，页面跳转至首页
```

需求未给库表或提示原文时，不要把示例里没有的字段/文案写成已确认事实。

用户要 `.xmind` 且仓库已有转换脚本才运行；没有脚本则交 Markdown 并说明。
