# XMind 格式测试用例规则

质量、范围声明、覆盖方法一律遵 `functional-testcase-design.md`。本文件只约束 **XMind 兼容 Markdown 的层级**。

XMind 精简版要长得像日常手写脑图：**按页面 / 入口 / 字段展开，标题即操作，叶子是预期**。不要长成「维度节点 + TC 编号 + 短标题」那种表格式脑图。

| 形态 | 叶子 |
|------|------|
| **精简版**（勾选 XMind 且未要求完整版） | 用例标题下只有 `预期结果`，其下用 `-` 写可判定明细；**无**前置条件、**无**测试步骤节点 |
| **完整版**（用户明确要可执行 / 含前置·步骤·预期） | 在精简版上补 `前置条件：…` 与 `测试步骤：`；预期仍用 `-` |

输出 `.md`，用 XMind 按标题导入，不直接生成 `.xmind`。不出 Excel。

路径：`testcases/{需求名称}-测试用例.md`（`-` 连接）。**同一需求只写一份文件**，不论条数；禁止拆成 `-01`/`-02`。用户指定了目录则写到该目录；仅当用户明确要求拆分时才分文件。

---

## 和测试要点、旧表格式脑图的差别

| | 本格式（日常脑图） | 不要写成 |
|--|-------------------|----------|
| 分组 | 页面 / Tab / 功能点 / 字段或规则分支 | `#### 功能测试` `#### 边界测试` 这类维度名 |
| 用例节点 | 一句可执行的「条件 + 操作」 | `TC1-001 …（P0）` |
| 判定 | 全部写在 `预期结果` 的子节点 | 把「成功 / 被拦截」硬塞进短标题，却不写预期 |
| 优先级 | 脑图上不标 | `（P0）` / `（P1）` |
| 前置 / 步骤 | 精简版不单独建节点（写进标题） | `前置条件`、`###### 测试步骤：` |

## 层级

导入 XMind 后，中心是 `#`，往外一圈是模块。Markdown 只有六级标题，所以 **「预期明细」必须用 `-`，不能再开 `#######`**。

| Markdown | 含义 | XMind |
|----------|------|-------|
| `#` | 全文仅一个。一份文件对应一次需求 / 迭代时：`# {需求名}` | 中心 |
| `## 范围声明` | 仅当有来源 / 不测 / 缺口 / 隐含规则时出现；内容遵 functional 2.2。导入后会变成与模块并列的第一枝，不要把它写成用例 | |
| `##` | 模块：页面、Tab、弹框、或一块业务能力（如「揽收超时识别」）。单模块也不可省 | 一级 |
| `###` | 功能点（如「查询」「排除规则」「导出场」） | 二级 |
| `####` | **场景分组**（字段、规则分支、页面区域）；该功能点无需再拆时，本级**直接写用例标题** | 三级 |
| `#####` | 有场景分组时：用例标题 | 四级 |
| `#####` 或 `######` | **仅** `预期结果` 四个字。有分组时用 `######`，无分组时用 `#####`（紧挨用例标题，不跳级） | 用例的子节点 |
| `-` | 预期明细，每条一个子主题 | 预期结果的叶子 |

**有分组**（筛选项、多字段、多规则分支时用这个，也是最常见写法）：

```text
## 模块
### 功能点
#### 字段或规则分支
##### 条件 + 操作
###### 预期结果
- 明细
```

**无分组**（该功能点下每条本身就是一个完整场景，不必再插一层空分组）：

```text
## 模块
### 功能点
#### 条件 + 操作
##### 预期结果
- 明细
```

不得跳级：`#` → `##` → `###` → `####`，有分组再 `#####` → `###### 预期结果`。禁止 `###` 下面直接 `#####`。禁止把 `预期结果` 写成普通列表项标题以外的名字（如「期望」「结果」）。

识别一条用例的办法：某个标题的**直接子标题**是 `预期结果`，该标题就是用例节点。

---

## 模块 / 功能点 / 场景分组怎么切

按**界面位置或业务能力**切，不要按验证维度切。

- **模块 `##`**：用户能指着说「这块」的单位。列表页的筛选区、弹框、另一个 Tab、一段定时任务、一次补数接口，都是模块。命名带上位置，如 `物流轨迹Tab-筛选区`、`异常轨迹Tab-导出`。
- **功能点 `###`**：模块里的一个动作或一块规则，如 `查询`、`列展示`、`入池幂等`。
- **场景分组 `####`**：同一功能点下再按**字段、对象、规则分支**拆，方便定位。分组可以只有一条，也可以不建：没有独有规则的字段不单独占一组。条数不按字段乘场景，遵 functional 3.1（共享规则只在代表字段写全，同类页签只写差异，映射表不按编码拆条）。
- **端到端**：复杂链路可单独建 `## 端到端流程`，下分 `### 基本流` / `### 备选流` / `### 异常流`，每条仍是「标题 → 预期结果」。收筛选条数时不要把主流程砍掉。

同一功能点内的等价类（空 / null / 未传）仍然合并。导入与在线编辑、推送与补数这类不同写入不要抽成跨模块的「公共校验」。细则见 functional 3.1。

## 用例标题

标题就是执行时要做的那件事：**谁、在什么数据 / 状态下、做什么操作**。判定写在预期里，不要另建步骤节点。

- 写进标题：关键数据、是否填写某条件、点哪个按钮、看哪一块。
- 不超过 **25 个汉字**（只数汉字；数字、字母、标点不计，见 functional 第四章）。超长先砍路径、字段清单，判定移入预期。
- 不要 `TC1-001`、不要末尾 `（P0）`、不要 `**` / `*` / 反引号、行尾不要空格。
- 差：`测试查询功能`、`单号精确查询只出命中行`、`TC1-001 合法号验证码注册成功（P0）`。
- 好：`仅填1个系统中存在的快递单号，不填创建时间，点击查询`。
- 代表字段上，上限内（2000 条成功）和超限（2001 条被拦截）结果不同，可以各写一条。不要在其他字段或另一个页签再写一遍。分隔符、重复值是否占上限，写进其中一条的预期。
- 文案、区间开闭、是否 trim 等需求没写死的，把「待确认」写在标题或预期里，不要只藏在范围声明。

`#####` / `####` 用例标题下：精简版只保留 `预期结果`。完整版在标题和 `预期结果` 之间用纯文本写 `前置条件：…`，用 `1. 2. 3.` 写步骤（不要再开「测试步骤」标题，以免和无分组时的 `##### 预期结果` 抢层级）。`预期结果` 作为标题时，文字必须恰好是 `预期结果`。

## 示例

### 精简版（优先按此）

```markdown
# 用户注册

## 范围声明
**需求来源**：…（有文档链接才写）
**不测**：不涉及登录鉴权。

### 需求缺口 / 需确认项
- 超限提示文案未给出。【待确认】

## 注册页-提交区

### 提交注册

#### 手机号
##### 仅填未注册的11位手机号和正确验证码，点击注册

###### 预期结果
- 注册成功，页面跳转至首页
- 创建该手机号对应账号

##### 输入已注册手机号和正确验证码后点击注册

###### 预期结果
- 拦截且不创建新账号
- 提示文案【待确认】

#### 验证码
##### 验证码过期后点击注册

###### 预期结果
- 提交被拒，须重新获取验证码
```

无场景分组时，用例标题落在 `####`，`预期结果` 用 `#####`：

```markdown
## 注册成功页

### 跳转
#### 注册成功后停留在结果页查看跳转

##### 预期结果
- 页面跳转至首页
```

复杂链路：

```markdown
## 端到端流程

### 基本流
#### 新号注册成功后立即用该号登录进入首页

##### 预期结果
- 登录成功
- 首页展示该账号信息
```

### 完整形态（仅用户明确要求：在精简版上补前置和步骤）

```markdown
##### 仅填未注册的11位手机号和正确验证码，点击注册

前置条件：该手机号未注册。

1. 打开注册页面
2. 输入手机号 13800001111
3. 获取并输入正确验证码
4. 点击注册

###### 预期结果
- 注册成功，页面跳转至首页
```

需求未给库表或提示原文时，不要把示例里没有的字段 / 文案写成已确认事实。

用户要 `.xmind` 且仓库已有转换脚本才运行；没有脚本则交 Markdown 并说明。
