# 人工评审指引

仅 XMind / Excel 生成任务使用。测试要点不写这份文件（要点文末已有「风险与回归提示」）。评审已有用例只出问题清单，不写这份文件。

用例定稿、不再改之后，由**主 agent** 写。写作子 agent 不写，评审 agent 不评，不进入评审轮次。用例之后又改过（含补条、改稿）：整份重抽，不在旧稿上改数字或补行。

路径：`{输出目录}/{需求名称}-评审指引.md`，与用例文件同一目录。不要写进 `work/`，不要写进用例或范围声明。

回复里给路径，以及三节各有多少条要拍。不贴全文。

---

## 一、材料与红线

材料只从这三处抽，不重新拆需求：

| 材料 | 用来填 |
|------|--------|
| 拆解文件 | 范围、不测、范围判断、缺口与待确认 |
| 需求原文 | 「需求出处」的章节；对不上写「需求未写明」 |
| 最终用例 | 模块与条数、【待确认】、未选定的分支式预期、点名「同一规则 / 只写差异」的句子、预期明细 |

折叠类：拆解「范围判断」与最终用例里的点名**合并**。不单信拆解——写作时多折进去的，拆解里往往没有。未纳入只搬运拆解里已经写下的判断，交付时不要临时把需求章节和用例对一遍再编一行。

条数：XMind 以「直接子标题是 `预期结果`」的标题为一条用例；CSV 一行一条。【高】只认 XMind 标题行末 `【高】`，或 CSV「优先级」列 = `高`。

红线：

- 不复查结构、标题长度、判定点是否合并。这些生成时已查过
- 【高】是阻塞发布。高危断言是第五节四个维度里命中至少两个。第 3 节不按【高】抽，第 2 节也不按【高】排
- 第 3 节不代替第 2 节。挡住执行、但只命中 1 个维度的待确认，仍然先在第 2 节拍
- 不得建议补写需求没要求的权限、安全、探索性场景
- 拉不到的材料（评论、图片、画板、鉴权失败）只放第 1 节。人补的是材料，或接受这版没覆盖到；不是业务规则，不进第 2 节
- 带倒条数只数这次交付目录里真实存在的用例文件

## 二、文档结构

空节写规定的那一句跳过，禁止用「无」或空表凑块。有遗留问题时，标题下加一行 `自动评审遗留 N 条，见当次回复。` 不抄 r1/r2 清单。有文档链接或文件名才写需求来源，没有就省略。

固定开头（遗留行、需求来源行按上一段决定写不写）：

```text
# {需求名称} 用例评审指引

评审对象：{用例文件名}

按 1 → 2 → 3 看。每节只填「你的结论」，不必通读用例。
结构、标题长度、条数是否按判定点合并，生成时已查过，这里不重复。
优先级【高】表示阻塞发布。高危断言是四个维度里命中至少两个。第 3 节不按【高】抽，第 2 节也不按【高】排。
第 3 节不代替第 2 节。挡住执行、但只命中 1 个维度的待确认，仍然先在第 2 节拍。
```

三节的表头固定如下。抽法见第三、四、五节。空节用跳过句替换整张表，保留节标题：

- 不测没有内容：`没有写明不测，跳过`
- 切分没有行：`没有额外切分要拍，跳过`
- 材料没拉全没有内容：删掉这个小标题，不写「无」
- 第 2 节没有行：`没有要拍的待确认，跳过`
- 第 3 节没有行：`没有跨过 2 个维度的断言，跳过`

「你的结论」列留空，给人填。只有第 3 节里已是【待确认】或未选定分支的行，预先写上「见第 2 节」。

```text
## 1. 看范围划分

先确认测哪块。范围划错了，后面两节都是在错的集合上复核。

### 纳入
| 模块 | 功能点 | 用例条数 | 其中【高】 |

要划出去的模块：

### 不测

### 请确认这些切分
| # | 类型 | 判断 | 依据 | 你的结论 |

### 材料没拉全

## 2. 拍板【待确认】

一个缺口一行。解释不抄进表。挡住执行、需求矛盾排在前面。

| # | 待确认 | 档 | 影响用例 | 不拍板会怎样 | 你的结论 |

## 3. 高危断言快查

一条断言命中至少 2 个维度才列入。条数是打分结果，不设上限，也不凑条数。

| # | 位置 | 断言原句 | 后果重 | 歧义 | 放大 | 人判 | 命中 | 带倒 | 需求出处 | 你的结论 |

## 回什么就够改

把上面填了结论的行贴回来即可。没填的行保持现在的写法。
范围结论用来改模块和切分；待确认结论用来替换对应【待确认】；断言结论只改那一条预期。
```

## 三、第 1 节怎么抽

纳入地图：一行一个模块。功能点多于一个时，在同一格里用顿号连起来，不拆成多行。用例条数、【高】条数按第一节的数法填写。

地图下固定留一行 `要划出去的模块：`，后面留空给人填。这一行用来划掉多测的块；切分表里的行覆盖不到它。

切分只列下面三类，有则写，没有不编：

| 类型 | 抽什么 | 结论 |
|------|--------|------|
| 折叠 | 共享规则只在代表字段或代表入口写过；用例里点名适用同一规则、不再单开的字段或入口 | 同意 / 要拆开： |
| 拆开 | 不同写入路径分开写的功能点 | 同意 / 要合并： |
| 未纳入 | 拆解「范围判断」里已记下的、需求里出现但本次不写用例的块，带上原因 | 同意 / 要补： |

依据写需求里的句子或「需求未提及」。不测清单来自拆解「不测」，逐条列出，不放进切分表。拆解没写不测，该小节用跳过句。

## 四、第 2 节怎么抽

来源有两处，合并成一个缺口一行：

1. 用例、范围声明、拆解「缺口与待确认」里的【待确认】。Excel 的「预期结果」和「备注」都要扫
2. 未选定的分支式预期：同一条预期对同一判定给出互相排斥的两种结果，且没有选定哪一种。没标【待确认】也要单独成行

分档：

| 档 | 判定 |
|----|------|
| 挡住执行 | 不拍板，这条用例无法判 Pass/Fail。缺的是规则、阈值、去向或状态 |
| 需求矛盾 | 需求里两处说法都在，必须选一边 |
| 不挡主路径 | 缺的是展示文案或次要提示。主流程的对错已经能判 |

影响用例写「模块 > 功能点 > 用例标题」。不超过 5 条写全；超过则写条数、模块和一条代表标题。影响用例是空的，写「尚未落到用例」——人仍在本行拍规则，改用例时要先把【待确认】补到对应用例上。

## 五、第 3 节怎么打分

打分对象是一条预期明细（XMind 的一个 `-`，或 CSV 预期里的一条），不是整条用例。先找共同前提：共同前提占一行，被它带倒的叶子明细不各占一行。

四个维度各要有自己的证据。说不出证据，记 0。维度二和维度四可以同时为「是」：文本不能唯一确定，记歧义；没定下来的又是走哪条路、用哪套口径，再记人判。只拿「文档没写」这一句证据，只能记歧义，不能再记人判。

**后果重。** 这句写错会直接造成业务损失，或让后续步骤整段走错。三类都算：计算或公式、精度 / 舍入 / 阈值方向、会驱动后续步骤的状态或标记。事后能改的损失，只要后果重，仍然记「是」。与后续步骤无关的跳转、文案、启用禁用，记 0。

**歧义。** 需求原文对不上一句唯一规则：没写、两处矛盾，或只给了例子。用例上通常已是【待确认】或未选定的分支式预期。需求里有明确句子、断言只是改写的，记 0。

**放大。** 这句是共同前提：改它，至少另外 2 条用例的预期要一起改，或同一规则跨了本次交付目录里两个及以上用例文件。必须写出带倒条数和位置（模块，跨文件时写文件名）。数不出来记 0。只被一条用例使用的叶子断言记 0。

**人判。** 要定的是行为走哪条路、用哪套口径，答案在业务或测试的现行做法里。只缺展示文案、不改变走哪条路的，记 0。

命中 = 四个「是」的个数。小于 2 不进表。

排序：命中数从高到低；同分时先有「后果重」的；再按带倒条数从高到低。

| 列 | 怎么填 |
|----|--------|
| 位置 | 写出这句断言的那条用例：模块 > 功能点 > 用例标题 |
| 断言原句 | 照抄预期里的那一条，不改写 |
| 需求出处 | 需求章节名。对不上写「需求未写明」 |
| 你的结论 | 该行已是【待确认】或未选定分支：写「见第 2 节」。其余留空。人填「认可」，或「改成：」加一句判定 |

行数很多时，先检查是不是把叶子断言各写了一行。是的话并回共同前提。不要为了缩短而删掉命中 ≥2 的行。

## 六、交稿前自查

1. 三节都在。空节是规定的那一句，不是空表
2. 第 2 节没有「评论 / 图片 / 画板没拉到」
3. 第 3 节每一行命中 ≥2，且等于该行「是」的个数
4. 放大为「是」的行，带倒写了条数和位置
5. 同一条共同前提只有一行
6. 没有建议补权限、安全或探索性场景
7. 已是【待确认】或未选定分支的高危行，结论是「见第 2 节」
8. 文件在用例同目录，文件名是 `{需求名称}-评审指引.md`
