# testcase-design

Cursor Agent Skill：把产品需求 / PRD 设计成可入库的功能测试用例或测试要点。

本仓库是一套给 AI Agent 读的规则，不是测试执行框架。Agent 读完 `SKILL.md` 与对应 `references/` 后，按你勾选的格式生成 Markdown / CSV。适用于「写用例、生成用例、设计用例、出测试要点、把飞书 Wiki/云文档转成用例」这类任务。

**只做单次设计与排版。** 不做执行已有用例、写自动化脚本、探索性测试，也不做「生成 → 多 Agent 评审 → 修复」闭环（闭环请用独立 skill `testcase-closed-loop`）。

---

## 功能用途

| 能力 | 说明 |
|------|------|
| 需求拆解后再写 | 先划清测什么 / 不测什么、显式规则、缺口，再生成；需求不完整会提示补全 |
| 四种交付物 | XMind 精简版（日常脑图结构）、Excel/CSV 完整可执行、XMind 完整可执行、只要测试要点 |
| 飞书需求取全 | Wiki / 云文档尽量拉齐正文、图片附件、画板、评论；拉不到的缺口写入范围声明，不把鉴权失败说成「文档没有」 |
| 覆盖有约束 | 设计时按 11 个维度自检；功能类不可缺；权限 / 安全默认不写（除非你明确要求，或涉及登录鉴权 / 资金 / 数据安全）。XMind 不输出维度节点 |
| 按判定点写 | 分组按页面 / 字段，条数按判定点。共享规则只在代表字段写全；同类页签只写差异；映射表不按编码拆。导入与编辑、推送与补数等不同写入仍各自写 |

## 安装

这是 **个人 Skill**，放到 Cursor 的 skills 目录后即可被 Agent 发现。

### 方式一：克隆到个人 skills 目录（推荐）

```bash
git clone https://github.com/zouaiyong/testcase-design.git ~/.cursor/skills/testcase-design
```

Windows PowerShell：

```powershell
git clone https://github.com/zouaiyong/testcase-design.git "$env:USERPROFILE\.cursor\skills\testcase-design"
```

### 方式二：作为项目 Skill 放到某个仓库里

把本仓库内容放到目标项目的 `.cursor/skills/testcase-design/`，只有打开该项目时才会加载。

目录必须包含 `SKILL.md`：

```text
testcase-design/
├── SKILL.md
├── references/
│   ├── functional-testcase-design.md
│   ├── testcase-xmind-guideline.md
│   ├── testcase-excel-guideline.md
│   └── testpoint-analysis-guideline.md
└── scripts/
    └── validate_testcase.py        # 产物结构自检；--fix-bom 给 CSV 补 BOM
```

安装后新开一轮对话（或确认 Cursor 已刷新 skills）。触发词示例：「写测试用例」「按这个需求出用例」「把 PRD 转成用例」「只要测试要点」。即使用户只说「写用例」「出个用例」「按这个需求测一下」且没提 XMind/Excel，Agent 也应使用本 skill。

## 使用方法

### 1. 把需求交给 Agent

任意一种即可：

- 粘贴 PRD / 需求正文
- 附上本地 Word、PDF、图片
- 给出飞书 Wiki / 云文档链接（Agent 会尽量取正文、图片、画板、评论）
- 口头描述功能点（不完整时会先问缺口）

直接说目标，例如：

> 根据这份需求写测试用例  
> 把这个飞书文档转成用例  
> 先只要测试要点，确认后再写用例

### 2. 勾选交付格式（未指定时必须先选）

未指定格式时，Agent **不会直接开写**，会让你从下面四项里选一项：

1. **XMind 精简版**（常用）：按页面 / 功能点 / 字段分组，标题写条件 + 操作，下挂预期结果；**没有** TC 编号、维度节点、前置条件和测试步骤
2. **Excel/CSV 完整可执行**：10 列 CSV，含前置、步骤、预期
3. **XMind 完整可执行**：Markdown 层级与精简版相同，但补上前置条件和测试步骤
4. **只要测试要点**：只回答「测什么」，输出后停步，**不**自动展开成用例

以下说法视为已指定，可跳过勾选：

- 「XMind / 思维导图」「Excel / CSV / 表格」
- 「完整版 / 可执行 / 含前置·步骤·预期」「精简版 / 只要标题」
- 「测试要点 / 测试点」

「直接产出、不要再问、按默认」但**没说出具体格式**时，仍然要勾选，不会擅自按 XMind 开写。同一对话里已经选过格式、只是让补条或改稿时，沿用上次格式。

### 3. Agent 按路由读规则并生成

| 你选的格式 | 产物 | Agent 会读 | 默认路径 |
|------------|------|------------|----------|
| XMind 精简版 | Markdown，导入 XMind | 设计规则 + XMind 指南 | `testcases/{需求名称}-测试用例.md` |
| Excel/CSV | UTF-8 BOM 的 10 列 CSV | 设计规则 + Excel 指南 | `testcases/{需求名称}-测试用例.csv` |
| XMind 完整可执行 | 带前置/步骤的 Markdown | 设计规则 + XMind 指南（完整形态） | 同上 `.md` |
| 测试要点 | Markdown 要点清单 | 要点指南；飞书来源再读设计规则第一节 | `testcases/{需求名称}-测试要点.md` |

你指定了输出目录时，写到该目录，不再额外镜像一份到 `testcases/`。同一需求只写**一份文件**，不因条数拆成 `-01` / `-02`。

仓库当前**没有** `.md` → `.xmind` / `.csv` 转换脚本。需要 `.xmind` 时：用 XMind 按标题导入生成的 Markdown。需要表格时：直接打开 CSV（Excel / WPS 均可）。

### 4. 测试要点确认后再写用例

选「只要测试要点」时，输出结束后 Agent 会停步，请你确认是否补充或调整。确认后再让它按 XMind 或 Excel 展开成用例。

## 四种产物长什么样

### XMind 精简版（默认 XMind）

层级不得跳级：`#` 需求 → `##` 模块（页面 / Tab / 业务能力）→ `###` 功能点 → `####` 场景分组（字段 / 规则分支；无需再拆则本级直接写用例标题）→ 用例标题 → `预期结果` → `-` 明细。

```markdown
# 用户注册

## 注册页-提交区

### 提交注册

#### 手机号
##### 仅填未注册的11位手机号和正确验证码，点击注册 【高】

###### 预期结果
- 注册成功，页面跳转至首页
```

精简版禁止出现「前置条件」「测试步骤」、`TC1-001`、`（P0）` 以及 `#### 功能测试` 这类维度标题。标题写清条件 + 操作，行末 `【高】`/`【中】`/`【低】`，正文不超过 25 个汉字。

### Excel / CSV 完整可执行

固定 10 列，顺序不可改：

`功能模块, 功能测试点, 验证维度, 用例标题, 优先级, 前置条件, 测试步骤, 预期结果, 实际结果, 备注`

- 编码：UTF-8 with BOM  
- 优先级只允许：`高` / `中` / `低`（对应 P0 / P1 / P2）  
- 生成时「实际结果」填 `—`

### XMind 完整可执行

在精简版每个用例标题下补：

- 前置条件（纯文本）
- `测试步骤：` + `1. 2. 3.`
- `预期结果`

### 测试要点

回答「测什么」，不是步骤、不是 TC、不是需求复述。层级到 `-`，行末 `【高/中/低】`。文末必有 `## 风险与回归提示`。

```markdown
# XX需求测试要点

## 用户管理
### 用户注册
#### 手机号与验证码
- 合法号验证码注册成功并落库 【高】
- 已注册号重复提交被拦截 【高】
```

## Agent 内部工作流

需求进入后，顺序是：

1. **勾选格式**（未指定则停步询问）
2. 按 `references/functional-testcase-design.md` **拆解与设计**（范围、方法、维度、形态覆盖）
3. 按对应格式文件 **排版输出**

有内容才写「范围声明」：需求来源（有文档链接才写）、不测范围、缺口 / 待确认。都空则整段省略，不会用「无」凑块。

覆盖维度固定 11 个，**设计时按此顺序自检**，XMind **不要**把它们写成标题节点：

功能测试、边界测试、异常测试、权限测试（按需）、安全测试（按需）、数据一致性测试、并发测试（按需）、集成测试（按需）、性能测试（按需）、兼容性测试（按需）、用户体验测试（按需）

维度命中才写，不按文档长短减项。查询 / 筛选：共享规则（精确、模糊、空格、批量上限、条件必填）只在代表字段写全；没有独有规则的字段不单开；另一个页签只写差异。映射表一个对象一条，编码写在预期里。导入与在线编辑、推送与补数仍分别写，不抽成公共校验。收条数时保留端到端主流程。

    └── validate_testcase.py                      # 产物结构自检；--fix-bom 给 CSV 补 BOM

维护约定：质量、范围声明、标题写法以 `functional-testcase-design.md` 为准；排版分别遵 xmind / excel / testpoint 指南。Agent 应按任务按需读取，不要一次读完 `references/`。

## 不适用

- 执行已经写好的用例、记录实际结果
- 编写自动化测试脚本（pytest / Playwright 等）
- 无需求文档的纯探索性测试
- 多 Agent 生成-评审-修复闭环（那是 `testcase-closed-loop`）

## 常见问题

**Q：为什么不直接写出用例？**  
未指定格式时必须先勾选，避免默认成 XMind 精简版却与你的入库格式不一致。

**Q：能不能只要标题清单、不要预期？**  
精简版仍然保留 `预期结果` 及其子节点。只要标题、没有预期，不符合本 skill 的精简版合同。

**Q：XMind 还要不要 TC 编号和 P0？**  
不要 TC 编号和 `（P0）`。优先级标在用例标题行末：`【高】` / `【中】` / `【低】`。Excel 写在优先级列，标题列不再标一遍。

**Q：飞书文档拉失败怎么办？**  
缺口会写进范围声明。鉴权 / token 问题需要先完成飞书 MCP / skill 登录，不会被报成「文档无评论、无画板」。

**Q：条数很多会不会拆成多个文件？**  
不会。同一需求写入一份文件；条数多时按功能点分段自检，但仍在同一文件里。
