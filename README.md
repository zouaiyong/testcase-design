# testcase-design

把产品需求 / PRD 设计成可入库的功能测试用例或测试要点。本仓库是给 AI Agent 读的规则，不是测试执行框架。

装好后对 Agent 说「写测试用例」「把这份 PRD 转成用例」「只要测试要点」即可。Agent 会先让你选交付格式，再按 `SKILL.md` 与 `references/` 生成 Markdown 或 CSV；也可以只评审你已有的用例。

XMind / Excel 会走写作 → 独立评审 → 自动修复（评审最多 2 轮），定稿后同目录再出一份人工评审指引。测试要点是单次输出，不走闭环。

不覆盖：执行已有用例、写自动化脚本、无需求文档的探索性测试。细则以 `SKILL.md` 为准。

---

## 安装

```bash
npx skills add zouaiyong/testcase-design
```

会装到 `~/.agents/skills/testcase-design`。WorkBuddy、Claude Code 不读这个目录，装完后让对应 Agent 把该路径软链接到自己的 skills 目录（WorkBuddy：`~/.workbuddy/skills/testcase-design`；Claude Code：`~/.claude/skills/testcase-design`）。Windows 建不了软链接就用目录联接。链好后新开一轮对话即可被发现。

也可以把本仓库直接放到上述目录。目录里必须有 `SKILL.md`。

## 使用

把需求交给 Agent（粘贴正文、本地 Word/PDF/图片，或飞书 Wiki / 云文档链接），并指定一种格式：

1. **XMind 版**（常用）：Markdown，用 XMind 按标题导入。每条只有编号、标题和预期，无前置、步骤
2. **Excel/CSV**：11 列 CSV，含编号、前置、步骤、预期。用 Excel / WPS 直接打开
3. **只要测试要点**：只回答「测什么」，输出后停步，不自动展开成用例

没说格式时 Agent 会先问，不会擅自按 XMind 开写。同一次对话里补条、改稿沿用上次格式；要点确认后再写成用例，要重新选 XMind 或 Excel。

默认写到 `testcases/{需求名称}-测试用例.md`（或 `.csv` / `-测试要点.md`）。指定了目录就写到该目录。同一需求一份文件，过程文件在 `{输出目录}/work/`。

人工评审指引与用例同目录。待确认回复「#N 结论是……」，高危断言打 ✗ 的回复编号即可。

评审已有用例：把 `.csv` / `.md`（`.xlsx` / `.xmind` 先另存）和需求交给 Agent，出问题清单、不改稿。

## 产物长什么样

**XMind**：`#` 需求 → `##` 模块 → `###` 功能点 → `####` 场景分组（可不拆，本级直接写用例）→ 用例标题 → `预期结果` → `-` 明细。标题开头 `TC-0001`，行末 `【高】`/`【中】`/`【低】`。

```markdown
# 用户注册

## 注册页-提交区
### 提交注册
#### 手机号
##### TC-0001 仅填未注册的11位手机号和正确验证码，点击注册 【高】
###### 预期结果
- 注册成功
- 页面跳转至首页
```

**Excel/CSV**：UTF-8 BOM，固定 11 列：

`用例编号, 功能模块, 功能测试点, 验证维度, 用例标题, 优先级, 前置条件, 测试步骤, 预期结果, 实际结果, 备注`

编号 `TC-0001` 起连续递增；优先级只允许 `高` / `中` / `低`；生成时「实际结果」填 `—`。

**测试要点**：回答「测什么」，行末 `【高/中/低】`，文末有 `## 风险与回归提示`。

```markdown
# XX需求测试要点

## 用户管理
### 用户注册
#### 手机号与验证码
- 合法号验证码注册成功 【高】
- 已注册号重复提交被拦截 【高】
```

仓库没有 `.md` → `.xmind` 转换器。要脑图时用 XMind 按标题导入 Markdown。

## 常见问题

**飞书文档拉失败？** 缺口写进范围声明。鉴权问题先完成飞书登录，不会被报成「文档无评论、无画板」。

**条数很多会拆文件吗？** 不会，同一需求一份文件。

**评审会不会死循环？** 不会。评审最多 2 轮；仍不过则主 Agent 最后修一遍交付，没修的进遗留文件和评审指引由你裁决。测试要点不参与闭环。

**中途断了怎么接着做？** 说「继续」并给同一个输出目录。Agent 读 `work/{需求名称}-STATE.md` 续跑。
