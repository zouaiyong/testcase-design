# testcase-design

Cursor Agent Skill：把产品需求 / PRD 设计成可入库的功能测试用例或测试要点。

本仓库是一套给 AI Agent 读的规则，不是测试执行框架。Agent 读完 `SKILL.md` 与对应 `references/` 后，按你选定的格式生成 Markdown / CSV，也能评审你已有的用例。适用于「写用例、生成用例、设计用例、出测试要点、把飞书 Wiki/云文档转成用例、评审已有用例」这类任务。

**XMind / Excel 生成走闭环**：写作 Agent 写 → 全新评审 Agent 评 → 主 Agent 自动修，评审最多 2 轮（初评 + 1 次增量复审）；用例定稿后，同一目录再出一份人工评审指引。测试要点仍是单次输出，不另出指引。不做执行已有用例、写自动化脚本、探索性测试。

---

## 功能用途

| 能力 | 说明 |
|------|------|
| 需求拆解后再写 | 先划清测什么 / 不测什么、显式规则、缺口，再生成；测什么已经清楚时，缺口标【待确认】后继续 |
| 三种交付物 | XMind 版（日常脑图结构）、Excel/CSV 完整可执行、只要测试要点 |
| 飞书需求取全 | Wiki / 云文档拉齐正文、图片附件、画板、评论，图片与画板转写成文字；拉不到的缺口写入范围声明，不把鉴权失败说成「文档没有」 |
| 覆盖有约束 | 设计时按 11 个维度自检；功能类不可缺。需求已写的角色与数据范围按权限写；没写的越权、注入默认不写。XMind 不输出维度节点 |
| 按判定点写 | 分组按页面 / 字段，条数按判定点。共享规则只在代表字段写全；同类页签只写差异；映射表不按编码拆。导入与编辑、推送与补数等不同写入仍各自写 |
| 独立评审闭环 | XMind / Excel 由写作 Agent 产出，新开评审 Agent 按 R 编号逐条挑刺、主 Agent 按清单自动修并留修复说明；评审最多 2 轮，复审仍不过的条目落遗留文件并进评审指引供你裁决 |
| 人工评审指引 | 用例定稿后写 `{需求名称}-评审指引.md`，与用例同目录。先看已保障项，再确认范围、拍板待确认、用 ✓/✗ 核对高危断言 |
| 评审已有用例 | 给用例文件和需求，按评审模板出问题清单，不改稿；别处来的用例，脚本的格式差异单列、不计入判定 |

## 安装

推荐用这条命令安装。它会把本仓库装进 `~/.agents/skills/testcase-design`。目录页在 [skills.sh](https://skills.sh)。

```bash
npx skills add zouaiyong/testcase-design
```

`~/.agents/skills/` 不是每个 Agent 都会读。WorkBuddy、Claude Code 就不读这个目录，装完后在它们里面发现不了。解决办法：打开对应的 Agent，让它把 `~/.agents/skills/testcase-design` 软链接到该产品自己的 skills 目录下（WorkBuddy 为 `~/.workbuddy/skills/testcase-design`，Claude Code 为 `~/.claude/skills/testcase-design`）。Windows 上如果建不了软链接，让它改用目录联接。链好后新开一轮对话即可被发现。

### 手动放到 skills 目录

把本仓库内容放到 `~/.agents/skills/testcase-design/`。不读这个目录的 Agent，按上面的办法做软链接。

目录必须包含 `SKILL.md`：

```text
testcase-design/
├── SKILL.md
├── references/
│   ├── testcase-design-rules.md
│   ├── testcase-xmind.md
│   ├── testcase-excel.md
│   ├── testpoint.md
│   ├── review-loop.md
│   └── review-guide.md          # 人工评审指引：何时写、三节怎么抽
└── scripts/
    └── validate_testcase.py        # 产物结构自检；--fix-bom 给 CSV 补 BOM
```

安装后新开一轮对话（或确认 Agent 已刷新 skills）。触发词示例：「写测试用例」「按这个需求出用例」「把 PRD 转成用例」「只要测试要点」。即使用户只说「写用例」「出个用例」「按这个需求测一下」且没提 XMind/Excel，Agent 也应使用本 skill。

## 使用方法

### 1. 把需求交给 Agent

任意一种即可：

- 粘贴 PRD / 需求正文
- 附上本地 Word、PDF、图片
- 给出飞书 Wiki / 云文档链接（Agent 会取正文、图片、画板、评论，图片与画板转写成文字）
- 口头描述功能点（连测哪块都定不下来时才先问；其余缺口标【待确认】后继续）

直接说目标，例如：

> 根据这份需求写测试用例  
> 把这个飞书文档转成用例  
> 先只要测试要点，确认后再写用例

### 2. 选择交付格式（未指定时必须先选）

未指定格式时，Agent **不会直接开写**，会让你从下面三项里选一项：

1. **XMind 版**（常用）：按页面 / 功能点 / 字段分组，标题写条件 + 操作，下挂预期结果；**没有** TC 编号、维度节点、前置条件和测试步骤
2. **Excel/CSV 完整可执行**：10 列 CSV，含前置、步骤、预期
3. **只要测试要点**：只回答「测什么」，输出后停步，**不**自动展开成用例

以下说法视为已指定，可跳过选择（只认说交付物的词，「飞书表格里的需求」「按这些测试点」这类说输入材料的不算）：

- 「XMind / 思维导图 / xmind格式」→ XMind 版
- 「Excel / CSV / 表格」「含前置·步骤·预期」→ Excel/CSV；只说「完整版」「可执行」不算
- 「测试要点 / 测试点」→ 只要测试要点
- 附了现成的用例文件说「照这个格式」→ 按该文件对应的那一项
- 工作区里已有这个需求的 STATE 文件且还没交付 → 按 STATE 里的格式续跑

「直接产出、不要再问、按默认」但**没说出具体格式**时，仍然要先选，不会擅自按 XMind 开写；无人值守运行时请在 prompt 里写明格式。同一对话里已经选过格式、只是让补条或改稿时，沿用上次格式；测试要点确认后展开成用例是新交付物，要重新选 XMind 或 Excel。

### 3. Agent 按路由读规则并生成

| 你选的格式 | 产物 | Agent 会读 | 默认路径 |
|------------|------|------------|----------|
| XMind 版 | Markdown，导入 XMind | 设计规则 + XMind 指南 | `testcases/{需求名称}-测试用例.md` |
| Excel/CSV | UTF-8 BOM 的 10 列 CSV | 设计规则 + Excel 指南 | `testcases/{需求名称}-测试用例.csv` |
| 测试要点 | Markdown 要点清单 | 设计规则 + 要点指南 | `testcases/{需求名称}-测试要点.md` |

XMind / Excel 由写作 Agent 产出，随后新开评审 Agent 评审、主 Agent 自动修（评审最多 2 轮）。用例定稿后，同目录写 `{需求名称}-评审指引.md`。人工只看四步：哪些已经有保障、范围边界、【待确认】、高危断言。待确认回复「#N 结论是……」，断言打 ✗ 的回复编号；拍板后 Agent 按结论改用例、重抽指引，不重开评审。需求原文、拆解、评审报告、修复说明、遗留清单、STATE 等过程文件放 `{输出目录}/work/`。测试要点由主 Agent 直接输出，不走闭环，也不出评审指引。

你指定了输出目录时，写到该目录，不再额外镜像一份到 `testcases/`。同一需求只写**一份文件**，不因条数拆成 `-01` / `-02`。

仓库当前**没有** `.md` → `.xmind` / `.csv` 转换脚本。需要 `.xmind` 时：用 XMind 按标题导入生成的 Markdown。需要表格时：直接打开 CSV（Excel / WPS 均可）。

### 4. 测试要点确认后再写用例

选「只要测试要点」时，输出结束后 Agent 会停步，请你确认是否补充或调整。确认后再让它选 XMind 或 Excel 展开成用例（走正常闭环，要点文件作为拆解输入）。

## 三种产物长什么样

### XMind 版

层级不得跳级：`#` 需求 → `##` 模块（页面 / Tab / 业务能力）→ `###` 功能点 → `####` 场景分组（字段 / 规则分支；无需再拆则本级直接写用例标题）→ 用例标题 → `预期结果` → `-` 明细。

```markdown
# 用户注册

## 注册页-提交区

### 提交注册

#### 手机号
##### 仅填未注册的11位手机号和正确验证码，点击注册 【高】

###### 预期结果
- 注册成功
- 页面跳转至首页
```

XMind 版禁止出现「前置条件」「测试步骤」、`TC1-001`、`（P0）` 以及 `#### 功能测试` 这类维度标题。标题写清条件 + 操作，行末 `【高】`/`【中】`/`【低】`，正文不超过 25 个汉字。

### Excel / CSV 完整可执行

固定 10 列，顺序不可改：

`功能模块, 功能测试点, 验证维度, 用例标题, 优先级, 前置条件, 测试步骤, 预期结果, 实际结果, 备注`

- 编码：UTF-8 with BOM  
- 优先级只允许：`高` / `中` / `低`（对应 P0 / P1 / P2）  
- 生成时「实际结果」填 `—`

### 测试要点

回答「测什么」，不是步骤、不是 TC、不是需求复述。层级到 `-`，行末 `【高/中/低】`。文末必有 `## 风险与回归提示`。

```markdown
# XX需求测试要点

## 用户管理
### 用户注册
#### 手机号与验证码
- 合法号验证码注册成功 【高】
- 已注册号重复提交被拦截 【高】
```

## Agent 内部工作流

需求进入后，顺序是：

1. **选择格式**（未指定则停步询问）
2. 主 Agent 按 `references/testcase-design-rules.md` 第一节 **取材并拆解**（取全需求并把图片 / 画板转写成文字；产出范围、不测、带 R 编号的原子需求清单、缺口、范围判断）。XMind / Excel 从这一步起写 `{输出目录}/work/{需求名称}-STATE.md`，中断后凭它续跑
3. XMind / Excel 走**生成-评审闭环**：派 1 个写作 Agent 写产物 → 主 Agent 跑 `validate_testcase.py` 并比对未覆盖的 R（返修最多 2 次）→ 新开评审 Agent 按 R 逐条初评 → 需改则主 Agent 过滤后自动修并留修复说明 → resume 评审 Agent 增量复审，**评审最多 2 次**；复审仍不通过，主 Agent 最后修一遍，没修的落 `work/{需求名称}-遗留.md`。用例定稿后按 `references/review-guide.md` 写人工评审指引，再交付。模板与红线见 `references/review-loop.md`
4. 测试要点：主 Agent 按要点指南**单次输出**，输出后停步等确认，不走闭环

有内容才写「范围声明」：需求来源（有文档链接才写）、不测范围（含条数限制砍掉的块）、缺口 / 待确认（含材料没拉到的）。都空则整段省略，不会用「无」凑块。

覆盖维度固定 11 个，**设计时按此顺序自检**，XMind **不要**把它们写成标题节点：

功能测试、边界测试、异常测试、权限测试、安全测试、数据一致性测试、并发测试、集成测试、性能测试、兼容性测试、用户体验测试

除功能类外命中才写，不按文档长短减项。细则见 `references/testcase-design-rules.md` 的 2.2。查询 / 筛选：需求写到的共享规则（如精确匹配、空格、批量上限、条件必填）只在代表字段写全；没有独有规则的字段不单开；另一个页签只写差异。映射表一个对象一条，编码写在预期里。导入与在线编辑、推送与补数仍分别写，不抽成公共校验。用户限条数时先砍低优先级、再砍已点名的同规则类，端到端主流程和功能类不砍，砍掉的记入范围声明与拆解。

## 仓库结构

```text
.
├── SKILL.md                                      # 入口：何时用、先选格式、产物路由
├── references/
│   ├── testcase-design-rules.md                  # 质量单一事实源：拆解 / 方法 / 维度 / 覆盖 / 标题规范
│   ├── testcase-xmind.md                         # XMind 日常脑图层级（模块/字段/操作标题/预期）
│   ├── testcase-excel.md                         # CSV 10 列物理格式
│   ├── testpoint.md                              # 测试要点写法与三重扫描
│   ├── review-loop.md                            # 闭环手册：落盘规范 / 写作·评审提示词模板 / 修复原则 / STATE
│   └── review-guide.md                           # 人工评审指引：定稿后写、三节怎么抽、四维打分
└── scripts/
    └── validate_testcase.py                      # 产物结构自检；--fix-bom 给 CSV 补 BOM
```

维护约定：流程、目录与轮次以 `SKILL.md` 为准，落盘与子 Agent 模板以 `review-loop.md` 为准；质量、范围声明内容、标题写法以 `testcase-design-rules.md` 为准；排版（含范围声明位置）分别遵 xmind / excel / testpoint 指南；人工评审指引以 `review-guide.md` 为准。Agent 应按任务按需读取，不要一次读完 `references/`。

## 不适用

- 执行已经写好的用例、记录实际结果
- 编写自动化测试脚本（pytest / Playwright 等）
- 无需求文档的纯探索性测试

## 常见问题

**Q：为什么不直接写出用例？**  
未指定格式时必须先选，避免默认成 XMind 版却与你的入库格式不一致。

**Q：能不能只要标题清单、不要预期？**  
XMind 版仍然保留 `预期结果` 及其子节点。只要标题、没有预期，不符合本 skill 的用例合同。

**Q：XMind 还要不要 TC 编号和 P0？**  
不要 TC 编号和 `（P0）`。优先级标在用例标题行末：`【高】` / `【中】` / `【低】`。Excel 写在优先级列，标题列不再标一遍。

**Q：飞书文档拉失败怎么办？**  
缺口会写进范围声明。鉴权 / token 问题需要先完成飞书 MCP / skill 登录，不会被报成「文档无评论、无画板」。

**Q：条数很多会不会拆成多个文件？**  
不会。同一需求写入一份文件；条数多时按功能点分段自检，但仍在同一文件里。

**Q：评审闭环会跑几轮？会不会死循环？**  
XMind / Excel 生成后，评审 Agent 初评 1 次；需改则主 Agent 自动修，再由原评审 Agent 增量复审 1 次，评审最多 2 次；收集阶段的结构返修也最多 2 次。复审仍不通过，主 Agent 最后修一遍直接交付，没修的条目写入 `work/{需求名称}-遗留.md` 并列进评审指引第 2 节由你裁决，不会无限循环。测试要点不参与闭环。

**Q：能评审我已有的用例吗？**  
能。给用例文件（`.csv` / `.md`；`.xlsx` / `.xmind` 先另存为 CSV / Markdown）和需求，Agent 按评审模板出问题清单，不改稿。没有需求时只评写法与格式、不评覆盖。别处来的用例，脚本按本 skill 格式合同报出的差异单列、不计入判定，除非你要求按本 skill 格式入库。

**Q：中途断了、换了会话怎么接着做？**  
说「继续」并给同一个输出目录即可。Agent 读 `work/{需求名称}-STATE.md`，按记录的阶段续跑：需求原文、拆解、产物已写的不重做，评审报告已落盘的不重评。
